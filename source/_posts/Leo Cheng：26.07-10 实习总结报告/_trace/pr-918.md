## 问题与原因

`sys_mprotect` 只检查范围首页是否已映射（`find_area(start_addr)`），范围中间或末尾的空洞被静默跳过。对「已映射、空洞、已映射」三段调用 `mprotect(addr, len)` 在 StarryOS 上返回 0。按映射情况推断地址布局的程序（垃圾回收器、地址检查工具、做写与执行互斥的即时编译器）会读到错误结果。

## 改动与影响范围

在修改任何映射之前，用已有的 `can_access_range` 以空访问掩码检查 `[addr, addr+len)` 是否被连续覆盖，遇到第一个空洞即返回 `ENOMEM`，整段保护位都不改动。

影响范围：只有带空洞的 `mprotect` 调用，结果从「成功」变为 `ENOMEM`；完全覆盖的调用行为不变。

```rust
let start_addr = VirtAddr::from(addr);
// man 2 mprotect: if any page in [addr, addr+len) lacks a mapping → ENOMEM.
// Linux validates the whole range, not just the first page: an unmapped hole
// in the middle of `[mapped][hole][mapped]` must fail instead of silently
// protecting only the mapped fragments. `can_access_range` with an empty
// access mask is a pure contiguous-coverage check (every area's flags
// trivially contain the empty set), so it returns false on the first gap.
// We pre-check and leave the mapping untouched on failure, i.e. report
// ENOMEM atomically without any half-applied protection — the errno real
// programs test for.
if !aspace.can_access_range(start_addr, length, MappingFlags::empty()) {
    return Err(AxError::NoMemory);
}
```

## 溯源复核（2026-09-29）

错误码与 Linux 一致，但失败时的副作用不同：

- Linux 按顺序逐个处理范围内的映射区，遇到空洞才返回 `ENOMEM`，空洞之前的映射区已经改成新保护位（下节 `mm/mprotect.c` 链接）。
- 本拉取请求先整体检查、再修改，失败时什么都不改。正文「保护位应用到空洞之前的前缀」一句描述的是 Linux，而实现选择了不修改前缀，两者不一致。

宿主实测（WSL 6.6.87）：三页读写映射挖掉中间一页后 `mprotect(整段, PROT_READ)` 返回 `ENOMEM`，`/proc/self/maps` 中空洞前一页变为 `r--p`，空洞后一页仍为 `rw-p`。

这一差异已由后续改动消除：#2261（周睿，2026-09-05，VMA 生命周期重构）把 `sys_mprotect` 改成按片段依次提交，遇到空洞返回 `ENOMEM` 且保留已提交的前缀，注释直接引用 `do_mprotect_pkey()`。本拉取请求的「整体预检」已不在当前代码中。

## Linux 依据

- 逐个映射区推进，映射区起点不接上一段终点即 `ENOMEM`：[mm/mprotect.c#L909-L918](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/mm/mprotect.c#L909-L918)

- 末尾没有覆盖到 `end` 同样 `ENOMEM`：[mm/mprotect.c#L977-L978](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/mm/mprotect.c#L977-L978)

## man 原文

[mprotect(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/mprotect.2?h=man-pages-6.19#n173)：

> ENOMEM Addresses in the range [addr, addr+size-1] are invalid for the address space of the process, or specify one or more pages that are not mapped. (Before Linux 2.4.19, the error EFAULT was incorrectly produced for these cases.)

man 只规定错误码，没有说明失败时空洞之前的部分是否已修改。
