## 问题与原因

两处与 Linux 不一致，都在身份设置系统调用上：

1. `setuid((uid_t)-1)` 与 `setgid((gid_t)-1)` 被当成普通编号接受。root 调用后真实、有效、保存三个编号都被写成 `0xFFFFFFFF`，凭据被污染；而 `-1` 在 `setresuid`/`setreuid` 里是「不修改」的占位值，两种语义在同一个值上冲突。Linux 在单参数设置函数里先用 `uid_valid()` 拒绝 `-1`，返回 `EINVAL`。
2. `setfsuid`/`setfsgid` 没有实现，分发表落空，返回 `ENOSYS`。依赖文件系统身份的程序（NFS 服务端一类）以及 `/proc/<pid>/status` 中 `Uid:`/`Gid:` 第四列的断言都无法工作。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `uid_valid()` | `syscall/sys.rs` | 新增私有判定，`-1` 为无效编号，与既有 `NOCHG` 常量配对 |
| `sys_setuid` / `sys_setgid` | `syscall/sys.rs` | 入口先判 `uid_valid`，无效返回 `EINVAL` |
| `sys_setfsuid` / `sys_setfsgid` | `syscall/sys.rs` | 新增。有 `CAP_SETUID`（`CAP_SETGID`）或目标等于真实、有效、保存、文件系统四个编号之一时才修改；无论成败都返回原文件系统编号；`-1` 只查询不修改 |
| 分发表 | `syscall/mod.rs` | 接上 `Sysno::setfsuid`、`Sysno::setfsgid` |

影响范围只限调用这四个系统调用的线程自身的凭据。`setresuid`/`setreuid` 等多参数设置函数里 `-1` 仍表示不修改，行为不变。未涉及用户命名空间映射：StarryOS 只有初始命名空间，`make_kuid()` 在这里是恒等映射，所以 `uid_valid` 直接比较原始值。

与 Linux 的差异：Linux 的 `setfsuid` 在目标等于当前文件系统编号时不提交新凭据（`kernel/sys.c#L925`），这里照写一遍，结果相同；Linux 的安全模块钩子 `security_task_fix_setuid()` 没有对应物。

## 代码对照

### `setuid`、`setgid` 拒绝 `-1`

合入前（`os/StarryOS/kernel/src/syscall/sys.rs`，入口不检查编号，`-1` 直接进入后面的权限判断）：

```rust
pub fn sys_setuid(uid: u32) -> AxResult<isize> {
    debug!("sys_setuid <= uid: {uid}");
    let thread = current();
    let thread = thread.as_thread();
    let old = thread.cred();
```

Linux（[kernel/sys.c#L659-L661](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/sys.c#L659-L661)，`__sys_setuid()` 的开头）：

```c
	kuid = make_kuid(ns, uid);
	if (!uid_valid(kuid))
		return -EINVAL;
```

Linux（[include/linux/uidgid.h#L103-L106](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/include/linux/uidgid.h#L103-L106)）：

```c
static inline bool uid_valid(kuid_t uid)
{
	return __kuid_val(uid) != (uid_t) -1;
}
```

本 PR（同一文件，`sys_setgid` 的入口加了同样的判定；当前 dev 上两处判定都在，错误类型换成 `StarryError::InvalidInput`）：

```rust
fn uid_valid(id: u32) -> bool {
    id != NOCHG
}
// ...
pub fn sys_setuid(uid: u32) -> AxResult<isize> {
    debug!("sys_setuid <= uid: {uid}");
    // Linux setuid(2) §ERRORS: "EINVAL — uid is not valid in this user namespace."
    // Single-arg setuid has no NOCHG sentinel; (uid_t)-1 must be rejected.
    if !uid_valid(uid) {
        return Err(AxError::InvalidInput);
    }
    let thread = current();
```

### `setfsuid`

合入前分发表里没有 `Sysno::setfsuid` 与 `Sysno::setfsgid` 两项，调用返回 `ENOSYS`。

Linux（[kernel/sys.c#L914-L933](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/sys.c#L914-L933)，`__sys_setfsuid()`）：

```c
	kuid = make_kuid(old->user_ns, uid);
	if (!uid_valid(kuid))
		return old_fsuid;

	new = prepare_creds();
	if (!new)
		return old_fsuid;

	if (uid_eq(kuid, old->uid)  || uid_eq(kuid, old->euid)  ||
	    uid_eq(kuid, old->suid) || uid_eq(kuid, old->fsuid) ||
	    ns_capable_setid(old->user_ns, CAP_SETUID)) {
		if (!uid_eq(kuid, old->fsuid)) {
			new->fsuid = kuid;
			if (security_task_fix_setuid(new, old, LSM_SETID_FS) == 0)
				goto change_okay;
		}
	}

	abort_creds(new);
	return old_fsuid;
```

本 PR（`os/StarryOS/kernel/src/syscall/sys.rs`，`sys_setfsgid` 同构）：

```rust
pub fn sys_setfsuid(fsuid: u32) -> AxResult<isize> {
    debug!("sys_setfsuid <= fsuid: {fsuid}");
    let thread = current();
    let thread = thread.as_thread();
    let old = thread.cred();
    let prev_fsuid = old.fsuid;

    // (uid_t)-1 = query-only: don't change, just return prev.
    if fsuid == NOCHG {
        return Ok(prev_fsuid as isize);
    }

    // Linux: setfsuid silently ignores an invalid fsuid but always returns the
    // previous fsuid (never reports error). Unprivileged callers may only set
    // fsuid to one of {uid, euid, suid, fsuid}; CAP_SETUID allows arbitrary.
    let allowed = old.has_cap_setuid()
        || fsuid == old.uid
        || fsuid == old.euid
        || fsuid == old.suid
        || fsuid == old.fsuid;

    if allowed {
        let mut new = (*old).clone();
        new.fsuid = fsuid;
        thread.set_cred(new);
    }
    // Always return previous fsuid, even when the request was ignored.
    Ok(prev_fsuid as isize)
}
```

## Linux 依据

- `uid_valid()`/`gid_valid()` 的定义就是「不等于 `-1`」：[include/linux/uidgid.h#L103-L111](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/include/linux/uidgid.h#L103-L111)
- `__sys_setuid()` 先 `make_kuid()` 再 `uid_valid()`，无效返回 `-EINVAL`：[kernel/sys.c#L659-L661](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/sys.c#L659-L661)
- `__sys_setgid()` 同样处理：[kernel/sys.c#L487-L489](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/sys.c#L487-L489)
- `__sys_setfsuid()`：无效编号直接返回旧值（#L915-L916），四个编号之一或有 `CAP_SETUID` 才修改（#L922-L930），所有出口都返回 `old_fsuid`：[kernel/sys.c#L904-L938](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/sys.c#L904-L938)
- `__sys_setfsgid()` 同构：[kernel/sys.c#L948-L982](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/sys.c#L948-L982)
- 多参数设置函数里 `-1` 是占位值，只在不为 `-1` 时才判有效性：[kernel/sys.c#L721-L728](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/sys.c#L721-L728)

## man 原文

[setuid(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/setuid.2?h=man-pages-6.19#n88)：

> EINVAL The user ID specified in uid is not valid in this user namespace.

[setgid(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/setgid.2?h=man-pages-6.19#n43)：

> EINVAL The group ID specified in gid is not valid in this user namespace.

[setfsuid(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/setfsuid.2?h=man-pages-6.19#n51)：

> setfsuid() will succeed only if the caller is the superuser or if fsuid matches either the caller's real user ID, effective user ID, saved set-user-ID, or current filesystem user ID.
>
> On both success and failure, this call returns the previous filesystem user ID of the caller.
