## 问题与原因

三个 procfs 文件在补丁之前没有可用的数据：

- `/proc/diskstats` 不存在。
- `/proc/net/dev` 有表头和每个接口一行，但 16 个数值列是写死的 0。`render_proc_net_dev` 遍历 `ax_net::interfaces()`，只取接口名。
- `/proc/mounts` 与 `/proc/<pid>/mounts` 都是一行写死的字符串 `proc /proc proc rw,nosuid,nodev,noexec,relatime 0 0`，没有根文件系统。

PR 正文举的受影响程序是 glances 的 DISK、NETWORK、FILESYS 区块与 node_exporter 的 diskstats、netdev、filesystem 采集器。根因是内核里没有可供这些文件读取的计数：块层不记读写次数，网络栈不记每接口的字节与包数。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| 块 I/O 计数 | `axfs-ng/src/block_runtime/device.rs` | 新增四个全局 `AtomicU64`（读次数、读扇区数、写次数、写扇区数）；`submit_io` 通过 `validate_io` 之后按 `RequestOp` 加一，扇区数为 `buf_len / 512`；`block_io_stats()` 导出 |
| `render_diskstats()` | `kernel/src/pseudofs/proc.rs` | 新增，输出一行：`254`、`0`、`vda`，后接 11 个统计列，其中只有读次数、读扇区数、写次数、写扇区数有值，其余写 0；注册为 `/proc/diskstats` |
| 每接口计数 | `ax-net/src/router.rs` | `DeviceHandle` 增加 rx/tx 字节与包数四个 `AtomicU64`；`enqueue_tx` 入队成功后记发送，`device_rx_worker` 把包放进共享接收队列后记接收，回环的两条路径（`Router` 的转发与 `dispatch_unicast_packet` 的直通）同时记收发 |
| `net_dev_stats()` | `ax-net/src/{router,service,lib}.rs` | 新增 `NetDevStats` 与逐层导出 |
| `render_proc_net_dev()` | `kernel/src/pseudofs/proc.rs` | 改为遍历 `ax_net::net_dev_stats()`，填入 rx/tx 的字节与包数，其余 12 列仍为 0 |
| `render_mounts()` | 同上 | 新增：第一行 `/dev/vda / <根文件系统类型> rw,relatime 0 0`，类型取自 `FS_CONTEXT` 根目录所在文件系统的名字；其后六行是写死的 `/dev`、`/dev/shm`、`/tmp`、`/proc`、`/sys`、`/sys/kernel/debug`。`/proc/mounts` 与 `/proc/<pid>/mounts` 都改用它 |

影响范围：读这三个文件的程序。计数用 `Ordering::Relaxed` 的原子加法，块提交路径每次多两次，网络收发路径每个包多两次（回环多四次）。

合入时与 Linux 的差异：

- `/proc/diskstats`：Linux 每个磁盘和每个分区一行，每行 3 个标识列加 17 个统计列；补丁只有一行，11 个统计列，没有 discard 与 flush 的 6 列。计数是所有块设备共用的全局量，设备名与主设备号写死为 `vda` 与 254。Linux 在请求完成时记次数与扇区数，补丁在提交时记，请求失败也已计入。主设备号在 Linux 里按 4 位宽右对齐，补丁行首没有空格。
- `/proc/net/dev`：字节数按 IP 包长计（`NetDevStats` 的文档注释写明）。Linux 的回环设备也是剥掉链路层头之后的长度，收发共用一组计数，这一点一致；以太网接口上 Linux 的驱动按含链路层头的帧长计（以 virtio-net 为例，见下），口径差一个以太网头。列之间用单个空格，没有按 Linux 的列宽对齐；接口名宽度是 8，Linux 是 6。
- `/proc/mounts`：不是遍历挂载树得到的。`mount(2)` 新增的挂载不会出现，卸载掉的也不会消失；挂载选项与根设备名 `/dev/vda` 是写死的。合入时 `pseudofs::mount_all()` 无条件挂载的正是这六处，另有按条件挂载的 `/dev/bus/usb` 与 `/sys/bus/usb` 没有列出。Linux 的 `/proc/mounts` 是指向 `self/mounts` 的符号链接，这里是普通文件。

当前 dev：

- 块计数移到 `fs/ax-fs-ng/src/block/runtime/lifecycle/mod.rs`（第 70 至 84 行），加一的位置改到请求完成回调 `request_completed`（`lifecycle/device.rs` 第 632 行），只在结果成功时计。`render_diskstats` 在 `os/StarryOS/kernel/src/pseudofs/proc.rs` 第 504 行，设备名与主次设备号改由 `ax_fs_ng::root::root_block_identity()` 给出，仍是一行、11 个统计列、全局计数。
- `NetDevStats` 在 `net/ax-net/src/router.rs` 第 74 行，增加了 `rx_errors`、`rx_dropped`、`tx_errors`、`tx_dropped`，字节数改按链路层帧长计；`render_proc_net_dev_from_stats`（`proc.rs` 第 438 行）按 Linux 的列宽输出。
- `render_mounts` 不再写死，移到 `os/StarryOS/kernel/src/pseudofs/proc_mountinfo.rs` 第 65 行，遍历 `mount_namespace().walk_tree()` 输出。`/proc/mounts` 仍是普通文件。

## 溯源复核

- PR 正文称 `/proc/diskstats` 用「14 列 Linux 布局」。本文对照的 Linux 版本每行是 20 列（`Documentation/admin-guide/iostats.rst` 写明 17 个统计量，前面再加主次设备号与设备名）。14 列是不含 discard 与 flush 统计的写法，按空白切分并只取前 14 列的解析器不受影响，但不是当前 Linux 的布局。当前 dev 仍是 14 列。
- 正文称计数来自「真实读写请求数」。合入的代码在提交时加一，不区分请求最终成功与否；`iostats.rst` 对这两列的定义是成功完成的读写次数。当前 dev 已改为完成且成功时才计。
- 正文称 `/proc/mounts`「渲染根文件系统加启动时无条件挂载的伪文件系统」，与 diff 一致，diff 里的注释也写明了动态挂载不在其中。标题里的「real data」对这个文件只成立一半：只有根文件系统类型是运行时读的，其余是常量。后来换成了遍历挂载树的实现，见上文。
- 回归用例 `syscall-test-diskstats` 合入时按设备名 `vda` 找行。当前 dev 的设备名来自 `root_block_identity()`，用例也已改为找 `nvme0n1` 行（`read_nvme()`），断言内容不变。

> /proc/mounts Before Linux 2.4.19, this file was a list of all the filesystems currently mounted on the system. With the introduction of per-process mount namespaces in Linux 2.4.19 (see mount_namespaces(7)), this file became a link to /proc/self/mounts, which lists the mounts of the process's own mount namespace. The format of this file is documented in fstab(5).
