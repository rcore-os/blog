## 问题与原因

`sys_mmap` 用 `end = (addr + length).align_up(page_size)` 计算映射末尾，随后 `length = end - aligned`。两步都没有溢出检查：`addr + length` 可以回绕；即使没有回绕，`align_up` 内部的 `raw_end + page_size - 1` 也可以在接近 `usize::MAX` 时回绕。回绕后 `end` 变成一个很小的值，`length` 是错误的范围。PR 正文说明这个错误范围会在后面被 `validate_region` 拦下，问题在于算术已经算错、非 `MAP_FIXED` 路径还会拿它去做空闲区查找。触发条件是 `addr` 接近地址空间顶端且 `length` 很大的请求，正常程序不会发出。

## 改动与影响范围

| 修改点 | 内容 |
|:--:|:--:|
| `addr + length` | 改为 `addr.checked_add(length)`，溢出返回 `EINVAL` |
| 向上对齐 | 对齐后检查 `end < raw_end`，回绕返回 `EINVAL` |

第二项是首轮评审指出后补的。影响范围：`mmap` 的入口，对 `MAP_FIXED` 与非 `MAP_FIXED` 请求都生效；未溢出的请求计算结果不变。

当前 dev：`sys_mmap` 里这段已被改写（`syscall/mm/mmap.rs` 第 277 至 281 行）。长度单独用 `checked_align_up(length, page_size)` 向上取整，`addr.checked_add(length)` 只在 `MAP_FIXED`、`MAP_FIXED_NOREPLACE` 时检查，溢出仍返回 `EINVAL`。`raw_end` 加 `end < raw_end` 的写法在 `sys_mmap` 里已不存在，同一文件的 `sys_mlock2` 等处用的是 `raw_end` 加 `checked_align_up`。

## 溯源复核

- 错误码与 Linux 不一致。Linux 不计算 `addr + len`：长度向上取整后为 0 返回 `ENOMEM`，长度超过 `TASK_SIZE` 返回 `ENOMEM`，`MAP_FIXED` 的地址满足 `addr > TASK_SIZE - len` 返回 `ENOMEM`。补丁在这些情况下返回 `EINVAL`。PR 正文写「Linux 的 `do_mmap` 在入口直接用溢出检查返回 EINVAL」，与对照版本的代码不符；回归用例的注释自己写明 Linux 在这里给的是 `ENOMEM`，所以断言同时接受两个错误码。当前 dev 仍返回 `EINVAL`。
- 合入时的检查对非 `MAP_FIXED` 请求也生效：提示地址加长度溢出就返回 `EINVAL`。Linux 对非 `MAP_FIXED` 的提示地址只做参考，提示不可用时转入正常查找，调用可以成功。当前 dev 已改为只对固定地址检查，这一差异不再存在。
- PR 正文没有随评审后的提交更新：只写了 `checked_add`，没有提后补的 `end < raw_end` 检查与回归用例。
- 回归用例只覆盖 `addr + length` 回绕这一条路径（`addr = ~0xFFF`、`length` 为 8 页）。评审要求的第二种输入，即 `addr + length` 未溢出但向上对齐回绕，没有用例。
- PR 没有给出用例在修复前失败的记录。按 PR 正文的说法，旧实现算出的错误范围会被 `validate_region` 拦下并返回错误，那么只断言「返回 -1 且错误码为 `EINVAL` 或 `ENOMEM`」的用例在修复前也可能通过。未实测，待核实。
- 回归用例已不在当前 dev 的树里，见「验证」。

## man 原文

[mmap(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/mmap.2?h=man-pages-6.19#n532)：

> EINVAL We don't like addr, length, or offset (e.g., they are too large, or not aligned on a page boundary).

[mmap(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/mmap.2?h=man-pages-6.19#n584)：

> ENOMEM We don't like addr, because it exceeds the virtual address space of the CPU.

man 对「太大」的参数同时列了 `EINVAL` 与 `ENOMEM`，实际走哪个以上面的内核代码为准。
