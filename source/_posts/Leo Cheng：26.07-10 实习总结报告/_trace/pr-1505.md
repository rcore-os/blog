## 问题与原因

两处互不相关的问题，都是 consul 与 etcd 在单节点回环上运行时撞到的。

**只读共享映射上的 `fdatasync` 返回 `EBUSY`。** etcd 的 bbolt 用 `PROT_READ | MAP_SHARED` 映射数据库文件，写入走 `pwrite`。`fdatasync` 回写页缓存之前，`protect_dirty_pages_before_writeback` 让每个映射着脏页的地址空间先把该页写保护，对应函数是 `mm/aspace/backend/file.rs` 的 `protect_dirty_page`。它的第一个匹配分支是「4K 页且带 `WRITE`」，只读映射的 4K 页不满足守卫条件，落到下一个分支，那个分支本意是处理非 4K 页，打一条告警后返回 `false`。上层据此返回 `ResourceBusy`，`fdatasync` 得到 `EBUSY`，etcd 启动时退出。

**`IP_PKTINFO`、`IPV6_RECVPKTINFO`、`IPV6_PKTINFO` 返回 `ENOPROTOOPT`。** `syscall/net/opt.rs` 的选项分发表里没有这三项。consul 的 UDP DNS 服务（miekg/dns）与 serf/memberlist 会在数据报套接字上打开它们，`setsockopt` 失败后 agent 退出。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `protect_dirty_page` | `mm/aspace/backend/file.rs` | 第一个分支改为匹配所有 4K 页；带 `WRITE` 时去掉写位并刷 TLB，不带时什么都不做；两种情况都返回 `true` |
| `sys_setsockopt` | `syscall/net/opt.rs` | `(IPPROTO_IP, IP_PKTINFO)` 读入一个 `int` 后丢弃，返回 0；`(IPPROTO_IPV6, IPV6_RECVPKTINFO)` 与 `(IPPROTO_IPV6, IPV6_PKTINFO)` 先过 `ensure_ipv6_socket`，再同样处理 |
| `sys_getsockopt` | 同上 | 这三项一律写回 0；IPv6 两项先过 `ensure_ipv6_socket` |
| `call_dispatch!` 兜底分支 | 同上 | 由 `_` 改成具名绑定，返回 `ENOPROTOOPT` 之前打一条 `debug!` |

影响范围：`fsync`、`fdatasync` 以及其他走 `protect_dirty_pages_before_writeback` 的回写路径；上述三个选项的 `setsockopt` 与 `getsockopt`。可写共享映射的行为不变。

与 Linux 的差异：

- 回写部分与 Linux 一致。Linux 回写前对共享映射里的每个 PTE 做写保护并清脏位，遇到既不脏也不可写的 PTE 直接跳过，没有失败路径。
- 三个选项只是被接受，没有实现。`setsockopt` 的值没有保存，`getsockopt` 恒为 0，Linux 读回的是刚设的值。`recvmsg` 不会带 `IP_PKTINFO` 或 `IPV6_PKTINFO` 控制消息。代码注释写明了前提：套接字只绑在一个回环地址上时，没有控制消息也能工作。
- `IPV6_PKTINFO` 的参数类型不同。Linux 的 `setsockopt(IPV6_PKTINFO)` 要一个 `struct in6_pktinfo`，长度不足返回 `EINVAL`；`getsockopt` 里没有这一项，返回 `ENOPROTOOPT`。补丁把它当成与 `IPV6_RECVPKTINFO` 相同的整型开关。

当前 dev：

- `protect_dirty_page` 已重写（`os/StarryOS/kernel/src/mm/aspace/backend/file.rs` 第 476 行），按页的反向映射逐个调用 `protect_file_mapping_slot`（`mm/aspace/mod.rs` 第 3191 行）。后者保留了本补丁的规则：PTE 不带 `WRITE` 时直接返回成功。
- 三个选项的处理没有变，`sys_getsockopt` 里在 `opt.rs` 第 528 至 543 行，`sys_setsockopt` 里在第 717 至 733 行。`os/StarryOS/kernel/src` 与 `net/ax-net/src` 里没有别处提到 `PKTINFO`，控制消息仍未实现。

## 溯源复核

- 正文称「像 Linux 一样接受这些选项」。只有「不返回 `ENOPROTOOPT`」这一点与 Linux 相同，见上文的三条差异。依赖控制消息取目的地址的程序（绑在通配地址上、要按收包地址回包的 UDP 服务）拿不到它，而 `setsockopt` 已经报告成功。
- 回归用例 `syscall-test-ip-pktinfo` 里有两条断言在 Linux 上不成立：`setsockopt(IP_PKTINFO, 1)` 之后断言 `getsockopt` 读回 0，Linux 读回 1；`setsockopt(IPPROTO_IPV6, IPV6_PKTINFO, &one, sizeof(int))` 断言返回 0，Linux 因长度小于 `sizeof(struct in6_pktinfo)` 返回 `EINVAL`。这两条断言在当前 dev 的用例里仍在（`src/main.c` 第 58、65 行）。
- 正文写 `syscall-test-ip-pktinfo` 为 8 条断言、`8 pass, 0 fail`。合入的用例是 10 条（`TEST_DONE(10)`），多出的两条是评审后加的「`AF_INET` 套接字上的 IPv6 选项返回 `ENOPROTOOPT`」。评审记录里 CI 的结果是 `10 pass, 0 fail`。正文没有随之更新。
- `syscall-test-mmap-ro-fdatasync` 已不在当前 dev 上，被 #2404（`test(starry): migrate bugfix and syscall probes to LTP`）删除，树里没有同名用例。只读映射脏页回写这条路径目前没有专门的回归用例。

## man 原文

[fsync(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/fsync.2?h=man-pages-6.19#n41)：

> fsync() transfers ("flushes") all modified in-core data of (i.e., modified buffer cache pages for) the file referred to by the file descriptor fd to the disk device (or other permanent storage device) so that all changed information can be retrieved even if the system crashes or is rebooted. This includes writing through or flushing a disk cache if present. The call blocks until the device reports that the transfer has completed.

[fsync(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/fsync.2?h=man-pages-6.19#n96) 列出的错误是 `EBADF`、`EINTR`、`EIO`、`ENOSPC`、`EROFS`、`EINVAL`、`EDQUOT`，没有 `EBUSY`。

[IP_PKTINFO(2const)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2const/IP_PKTINFO.2const?h=man-pages-6.19#n22)：

> Pass an IP_PKTINFO ancillary message that contains a in_pktinfo(2type) structure that supplies some information about the incoming packet. This works only for datagram oriented sockets. The argument is a flag that tells the socket whether the IP_PKTINFO message should be passed or not.

[IPV6_RECVPKTINFO(2const)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2const/IPV6_RECVPKTINFO.2const?h=man-pages-6.19#n22)：

> Set delivery of the IPV6_PKTINFO control message on incoming datagrams. Such control messages contain a struct in6_pktinfo, as per RFC 3542. Allowed only for SOCK_DGRAM or SOCK_RAW sockets.

## 验证

- `syscall-test-mmap-ro-fdatasync`：在 ext4 上建一个两页的文件，`mmap(PROT_READ, MAP_SHARED)` 后读一遍触发缺页，经 fd `pwrite` 改第 0 页后 `fdatasync` 返回 0，改第 1 页后 `fsync` 返回 0，`munmap` 后用另一个 fd `pread` 读回新数据。
- `syscall-test-ip-pktinfo`：`AF_INET` 数据报套接字上 `IP_PKTINFO` 的 set、get 返回 0 且读回 0；`AF_INET6` 数据报套接字上 `IPV6_RECVPKTINFO`、`IPV6_PKTINFO` 的 set 与 `IPV6_RECVPKTINFO` 的 get 返回 0；`AF_INET` 套接字上 `IPV6_RECVPKTINFO` 的 set、get 返回 `ENOPROTOOPT`。
- PR 正文：四个架构跑 `cargo xtask starry test qemu --arch <arch> -c qemu-smp1/system` 都以 `rc=0` 结束并输出 `STARRY_GROUPED_TESTS_PASSED`。x86_64 上做过回退对照：去掉两处修复后，前一个用例在 `fdatasync` 与 `fsync` 的断言上失败（`errno=16`），后一个在 set 与 get 的断言上失败（`errno=92`）；修复后都通过。
- 评审记录（ZR233）：第一轮指出 IPv6 两项绕过了 `ensure_ipv6_socket`，`AF_INET` 套接字上也返回成功，改后复审通过。CI 运行 `28764540695` 为 28 项通过、28 项按预期跳过；x86_64 与 aarch64 的日志里 `test-ip-pktinfo` 为 `10 pass, 0 fail, 10/10 checks run`，`test-mmap-ro-fdatasync` 为 `11 pass, 0 fail, 11/11 checks run`。
