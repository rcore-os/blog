## 问题与原因

三处互相独立的问题，PR 正文把它们归到全屏终端程序（glances、htop、textual、casca）在串口控制台上的表现。

1. `ioctl(fd, FIOCLEX)`（`0x5451`）与 `ioctl(fd, FIONCLEX)`（`0x5450`）在非终端的描述符上失败。`sys_ioctl` 只在入口处理了 `FIONBIO` 与 `FIOASYNC`，其余命令交给文件对象自己的 `ioctl`；管道、普通文件这类对象不认识这两个命令，返回 `NotATty`，并打印 `Unsupported ioctl command: 21585`。Linux 把这两个命令放在通用层处理，对任何描述符都有效。
2. `/proc/<pid>/status` 没有 `voluntary_ctxt_switches` 与 `nonvoluntary_ctxt_switches` 两行。按 PR 正文，psutil 的 `Process.num_ctx_switches()` 找不到这两行时抛出 `NotImplementedError`，glances 的进程视图因此崩溃，回溯信息打在 curses 画面上。这一因果只有正文为据。
3. 文件对象返回 `NotATty` 时，`sys_ioctl` 除五个列名的命令（`TIOCGWINSZ`、`TCGETS`、`BLKGETSIZE64`、`BLKRAGET`、`BLKSSZGET`）外都打一条 `warn!`。libc、ncurses、CPython 对各个描述符做终端探测时触发这条日志，日志与全屏程序共用串口，画面被冲乱。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `FIOCLEX`、`FIONCLEX` | `syscall/fs/ctl.rs` 的 `sys_ioctl` | 定义两个常量；在 `FIONBIO`、`FIOASYNC` 之后、调用文件对象的 `ioctl` 之前拦下这两个命令，把 `FD_TABLE` 中该描述符的 `cloexec` 置为 `cmd == FIOCLEX`，返回 0。无效描述符由入口的 `get_file_like(fd)` 返回 `EBADF` |
| 上下文切换计数 | `pseudofs/proc.rs` 的 `render_task_status_fields` | 在 `Mems_allowed_list` 之后追加两行，值固定为 0 |
| 日志级别 | `sys_ioctl` 的错误分支 | `NotATty` 一律改为 `debug!`，去掉五个命令的白名单；返回给用户态的错误不变 |

影响范围：`ioctl` 的 `FIOCLEX`、`FIONCLEX` 两个命令，以及由此改变的 `execve` 时描述符去留；读 `/proc/<pid>/status` 与 `/proc/self/status` 的程序；内核日志。

与 Linux 的差异：

- 两个计数恒为 0，Linux 输出的是任务的 `nvcsw` 与 `nivcsw`。正文已说明这是占位。
- `O_PATH` 描述符上的 `FIOCLEX`、`FIONCLEX` 返回 0，Linux 返回 `EBADF`，见「溯源复核」。

当前 dev：

- `FIOCLEX`、`FIONCLEX` 仍在 `syscall/fs/ctl.rs`（常量在第 39、40 行，分支在第 112 至 117 行），改为调用 `current_fd_table().write().set_cloexec()`。
- 两行计数仍在 `pseudofs/proc.rs` 第 883、884 行，值仍是 0。
- `NotATty` 的 `debug!` 仍在 `syscall/fs/ctl.rs` 第 127 行。

## 溯源复核

- `O_PATH` 描述符的处理与 Linux 不同。Linux 的 `ioctl` 入口用 `fdget()` 取文件，`fdget()` 排除带 `FMODE_PATH` 的文件，所以对 `O_PATH` 描述符的任何 `ioctl`（包括 `FIOCLEX`）都返回 `EBADF`；这类描述符的 close-on-exec 标志只能经 `fcntl(F_SETFD)` 修改。当前 dev 的 `sys_ioctl` 入口只有 `get_file_like(fd)`，没有 `fd_is_path` 判断（`syscall/fs/ctl.rs` 第 93 至 117 行），`FIOCLEX` 分支对 `O_PATH` 描述符返回 0 并修改标志。回归用例没有覆盖 `O_PATH`。
- 日志降级的范围比标题里的「探测」宽。文件对象对自己不认识的命令也返回 `NotATty`，原来的 `warn!` 是发现这类缺口的线索，本 PR 的第一项就是从 `Unsupported ioctl command: 21585` 这条日志定位的。降级后，默认日志级别下看不到任何未实现的 `ioctl` 命令。
- 用例注释把 `FIOCLEX` 的出处写成「man 2 ioctl_tty」。man-pages 6.19 的 `ioctl_tty.2` 里这两个命令只出现在被注释掉的源码行里（第 184、185 行），渲染后的手册没有它们的条目，见「man 原文」。

## man 原文

man-pages 6.19 没有 `FIOCLEX`、`FIONCLEX` 的专门条目，渲染后提到它们的只有 [landlock(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/landlock.7?h=man-pages-6.19#n116)：

> IOCTL commands targeting file descriptors (FIOCLEX, FIONCLEX),

它们设置的标志见 [F_GETFD(2const)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2const/F_GETFD.2const?h=man-pages-6.19#n22)：

> These operations manipulate the flags associated with a file descriptor. Currently, only one such flag is defined: FD_CLOEXEC, the close-on-exec flag. If the FD_CLOEXEC bit is set, the file descriptor will automatically be closed during a successful execve(2).

[ioctl(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/ioctl.2?h=man-pages-6.19#n66)：

> EBADF fd is not a valid file descriptor.

[ioctl(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/ioctl.2?h=man-pages-6.19#n84)：

> ENOTTY The specified operation does not apply to the kind of object that the file descriptor fd references.

[open(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/open.2?h=man-pages-6.19#n592)：

> Obtain a file descriptor that can be used for two purposes: to indicate a location in the filesystem tree and to perform operations that act purely at the file descriptor level. The file itself is not opened, and other file operations (e.g., read(2), write(2), fchmod(2), fchown(2), fgetxattr(2), ioctl(2), mmap(2)) fail with the error EBADF.

[proc_pid_status(5)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man5/proc_pid_status.5?h=man-pages-6.19#n391)：

> voluntary_ctxt_switches nonvoluntary_ctxt_switches Number of voluntary and involuntary context switches (since Linux 2.6.23).

## 验证

- `syscall-test-ioctl-cloexec`（15 条断言）：在管道描述符上，`FIOCLEX` 返回 0 且 `fcntl(F_GETFD)` 看到 `FD_CLOEXEC` 置位；`FIONCLEX` 返回 0 且标志清除；`fcntl(F_SETFD, FD_CLOEXEC)` 置位后再用 `FIONCLEX` 清除，两条路径互相可见；对 `-1` 与已关闭的描述符返回 `EBADF`。
- `syscall-test-procfs-ctxt-switches`（4 条断言）：`/proc/self/status` 与 `/proc/<pid>/status` 各有这两行，冒号后能解析出整数。只检查存在与可解析，不检查数值。
- 作者 2026-06-10 的评论：x86_64、aarch64、riscv64、loongarch64 单核 QEMU 下两个用例分别 15/15、4/4。评审通过时记录最新 CI 通过，并在本地跑过这两个用例。
- PR 正文：含本修复的内核上，glances 与 htop 的画面经 `pyte` 离线渲染检查无回溯、无冲乱；textual、casca 的用例在四个架构上各 9/9。
- 日志级别的改动没有对应用例。
- 当前 dev 仍保留这两个用例，位置是 `test-suit/starryos/qemu/system/syscall-test-ioctl-cloexec` 与 `test-suit/starryos/qemu/system/syscall-test-procfs-ctxt-switches`。
