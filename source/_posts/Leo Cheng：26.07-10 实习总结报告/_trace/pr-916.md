## 问题与原因

x86_64 上按 ABI 偏移直接读写信号上下文的运行时会弄坏寄存器。典型是 Go 的异步抢占：`SIGURG` 处理函数读写 `uc_mcontext.gregs[REG_RSP]` 与 `REG_RIP`，再由 `rt_sigreturn` 按写回的值恢复。StarryOS 上读到的 `RSP` 错位 8 字节，Go 报 `unsafe.Slice: len out of range`。

根因在对齐：`MContext`（对应 Linux 的 `struct sigcontext`）标了 `#[repr(C, align(16))]`。Linux 的 `sigcontext` 是自然 8 字节对齐，在 `ucontext` 里紧跟 `uc_flags`、`uc_link`、`uc_stack`（共 40 字节），偏移为 40。强制 16 字节对齐后，编译器在 `uc_stack` 之后补 8 字节，`uc_mcontext` 落到 48，其中每个寄存器都错一格。

## 改动与影响范围

| 修改点 | 内容 |
|:--:|:--:|
| `MContext` | `repr(C, align(16))` 改为 `repr(C)`，恢复偏移 40 |
| `UContext` | `repr(C)` 改为 `repr(C, align(16))`，信号帧的 16 字节对齐改由外层结构保证 |
| 编译期断言 | `offset_of!(UContext, mcontext) == 40`、`offset_of!(UContext, sigmask) == 296`，偏移再被改错即编译失败 |

影响范围：只有 x86_64 的信号帧布局，其他架构与调用方不动。所有在处理函数里读写 `ucontext` 的程序（Go、JVM 的安全点与空指针检查、各类协程库）都依赖这一布局。

当前 dev 中该文件已移到 `os/StarryOS/signal/src/arch/x86_64.rs`，两条断言仍在（第 401–402 行），`MContext` 为 `repr(C)`、`UContext` 为 `repr(C, align(16))`。

Linux（[include/uapi/asm-generic/ucontext.h#L5-L11](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/include/uapi/asm-generic/ucontext.h#L5-L11)）：

```c
struct ucontext {
	unsigned long	  uc_flags;
	struct ucontext  *uc_link;
	stack_t		  uc_stack;
	struct sigcontext uc_mcontext;
	sigset_t	  uc_sigmask;	/* mask last for extensibility */
};
```

Linux（[arch/x86/kernel/signal.c#L135-L144](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/arch/x86/kernel/signal.c#L135-L144)，帧的对齐在放置时计算，`FRAME_ALIGNMENT` 为 16）：

```c
	sp -= frame_size;

	if (ia32_frame)
		/*
		 * Align the stack pointer according to the i386 ABI,
		 * i.e. so that on function entry ((sp + 4) & 15) == 0.
		 */
		sp = ((sp + 4) & -FRAME_ALIGNMENT) - 4;
	else
		sp = round_down(sp, FRAME_ALIGNMENT) - 8;
```

## Linux 依据

- `struct ucontext` 字段顺序：[include/uapi/asm-generic/ucontext.h#L5-L11](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/include/uapi/asm-generic/ucontext.h#L5-L11)。`uc_flags`、`uc_link` 各 8 字节，`stack_t` 24 字节，`uc_mcontext` 因而在 40
- x86_64 的 `struct sigcontext` 全由 8 字节以内的成员组成，共 256 字节，`uc_sigmask` 因而在 296：[arch/x86/include/uapi/asm/sigcontext.h#L325-L385](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/arch/x86/include/uapi/asm/sigcontext.h#L325-L385)
- 信号帧 16 字节对齐在放帧时处理，不靠 `sigcontext` 自身对齐：[arch/x86/kernel/signal.c#L85-L86](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/arch/x86/kernel/signal.c#L85-L86)、[arch/x86/kernel/signal.c#L144](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/arch/x86/kernel/signal.c#L144)

## man 原文

[sigaction(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/sigaction.2?h=man-pages-6.19#n296)：

> ucontext This is a pointer to a ucontext_t structure, cast to void *. The structure pointed to by this field contains signal context information that was saved on the user-space stack by the kernel; for details, see sigreturn(2). Further information about the ucontext_t structure can be found in getcontext(3) and signal(7).

man 只说明 `ucontext_t` 由内核保存在用户栈上，字段偏移以内核头文件为准。
