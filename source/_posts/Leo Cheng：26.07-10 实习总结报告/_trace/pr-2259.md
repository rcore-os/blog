## 问题与原因

`sys_arch_prctl` 对 `ArchPrctlCode::GetCpuid`（`ARCH_GET_CPUID`，`0x1011`）固定返回 `Ok(0)`。按 Linux 的约定，这个返回值是「`cpuid` 指令对本线程是否可用」：1 为可用，0 为已禁用（执行 `cpuid` 会收到 `SIGSEGV`）。StarryOS 没有实现 CPUID faulting，`cpuid` 指令始终可以执行，返回 0 与实际状态相反。

用这个调用探测 CPUID 状态的程序会把「可用」读成「已被禁用」。PR 正文举的例子是 glibc 与 SDE 这类插桩工具，没有附具体的失败现场。

## 改动与影响范围

`sys_arch_prctl` 的 `ArchPrctlCode::GetCpuid` 分支由 `Ok(0)` 改为 `Ok(1)`，并加一段注释说明理由。`ArchPrctlCode::SetCpuid` 分支没有改，仍返回 `NoSuchDevice`（`ENODEV`）。

影响范围：只有 x86_64 上的 `arch_prctl(ARCH_GET_CPUID)`。`ARCH_SET_FS`、`ARCH_GET_FS`、`ARCH_SET_GS`、`ARCH_GET_GS` 四个分支未动。

与 Linux 的差异：Linux 的 `ARCH_SET_CPUID` 只在硬件不支持 CPUID faulting 时返回 `ENODEV`，支持时按参数置位或清除线程的 `TIF_NOCPUID`，`ARCH_GET_CPUID` 读的就是这个标志。StarryOS 不检测硬件能力，`ARCH_SET_CPUID` 一律 `ENODEV`，状态因此恒为「可用」，`ARCH_GET_CPUID` 恒返回 1 与之自洽。

当前 dev：两个分支在 `syscall/task/thread.rs` 第 130、131 行，注释在第 125 至 129 行，内容与补丁相同。

## 溯源复核

- PR 正文、内核注释与测试都把返回值 1、0 称作 `ARCH_CPUID_ENABLE`、`ARCH_CPUID_SIGSEGV`。Linux 里没有这两个名字：uapi 头文件只定义了 `ARCH_GET_CPUID` 与 `ARCH_SET_CPUID` 两个操作码，`get_cpuid_mode()` 直接返回 `!test_thread_flag(TIF_NOCPUID)`；在固定版本源码的 `arch/x86`、`include/uapi`、`tools/arch/x86` 下都搜不到这两个标识符。数值 1 与 0 是对的，名字是测试自己用 `#define` 起的。内核注释里的 `1 (ARCH_CPUID_ENABLE)` 在当前 dev 上还在（`thread.rs` 第 125 行）。
- 承载 D 段的用例 `syscall-test-archprctl-tls` 已不在当前 dev 上：#2404（2026-09-14 合入）删除了它的三个文件。当前 dev 的 `test-suit` 里搜不到对 `ARCH_GET_CPUID` 的断言。

## man 原文

[arch_prctl(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/arch_prctl.2?h=man-pages-6.19#n75)：

> ARCH_GET_CPUID (since Linux 4.12) Return the setting of the flag manipulated by ARCH_SET_CPUID as the result of the system call (1 for enabled, 0 for disabled). addr is ignored.

[arch_prctl(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/arch_prctl.2?h=man-pages-6.19#n44)：

> ARCH_SET_CPUID (since Linux 4.12) Enable (addr != 0) or disable (addr == 0) the cpuid instruction for the calling thread. The instruction is enabled by default. If disabled, any execution of a cpuid instruction will instead generate a SIGSEGV signal.

[arch_prctl(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/arch_prctl.2?h=man-pages-6.19#n128)：

> ENODEV ARCH_SET_CPUID was requested, but the underlying hardware does not support CPUID faulting.
