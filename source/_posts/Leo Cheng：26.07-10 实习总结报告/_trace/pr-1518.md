## 问题与原因

`setsockopt(SOL_SOCKET, SO_REUSEPORT)` 返回 `ENOPROTOOPT`：`syscall/net/opt.rs` 的选项分发表里这一项是注释掉的 `TODO: needs kernel support`，调用落到兜底分支。Envoy 默认对每个 listener 设这个选项，创建 listener 因此失败，这是 [#1502](pr-1502.md) 里 higress 应用测试撞到的问题。

只接受选项还不够。ax-net 有三张按端口登记占用的表，都不认识「共享」：TCP 的 `TCP_BOUND_PORTS` 是每端口一个地址集合，`register_tcp_bound` 遇到地址冲突就返回 `EADDRINUSE`；`LISTEN_TABLE` 每个端点只容一个 listener；UDP 的 `udp_binds` 以（地址，端口）为键，一个键只有一个 socket。两个都设了 `SO_REUSEPORT` 的 socket 绑同一地址端口，第二个仍会失败。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `ReusePort(bool)` | `options.rs`、`general.rs` | 新增选项；`GeneralOptions` 增加 `reuse_port` 标志，`get_option`、`set_option` 读写它，与 `reuse_address` 互不影响 |
| 选项分发 | `kernel/src/syscall/net/opt.rs` | 增加 `(SOL_SOCKET, SO_REUSEPORT) => ReusePort as IntBool`，删掉原来的 TODO 注释 |
| `TcpSocket::bind` | `tcp.rs` | 监听表的预检查（`LISTEN_TABLE.can_listen`）在设了 `reuse_port` 时也跳过，与设了 `reuse_address` 时相同 |
| `register_tcp_bound(endpoint, reuse_port)` | 同上 | `TCP_BOUND_PORTS` 改为每端口一个 `TcpBoundEntry { addr, reuse_port }` 列表，按下述规则判断冲突；`unregister_tcp_bound` 删掉一条地址相同的记录 |
| `ListenTable::listen(endpoint, backlog, reuse_port)` | `listen_table.rs` | `ListenTableEntryInner` 增加 `reuse_port`；按同一规则允许同一端点登记多个表项 |
| `udp_bind(handle, addr, port, reuse_port)` | `wrapper.rs` | `udp_binds` 改为每端口一个 `UdpBoundEntry { addr, reuse_port, handle }` 列表，冲突判断抽成 `udp_binds_conflict`；`udp_unbind` 按 `handle` 删 |
| `UdpSocket::bind` | `udp.rs` | 改为无条件调用 `udp_bind` 并传入 `reuse_port`；原来「设了 `SO_REUSEADDR` 就不登记」的条件删掉 |

三张表用同一条规则：新绑定与同端口上某条记录地址冲突（任一方是通配地址，或两者相同）时，只有双方都设了 `SO_REUSEPORT` 且地址完全相同才放行，否则返回 `EADDRINUSE`。

影响范围：`SO_REUSEPORT` 的 `setsockopt` 与 `getsockopt`；TCP 的 `bind`、`listen`、`close`；UDP 的 `bind`、`close`。`GeneralOptions` 嵌在 TCP、UDP、raw、AF_UNIX、vsock 各类套接字里，选项本身不限于 TCP 与 UDP。

与 Linux 的差异：

- 不比较 UID。Linux 要求组内 socket 的属主 UID 相同，补丁没有记录也没有比较。
- 地址必须完全相同。Linux 的冲突判断只看双方的 `sk_reuseport` 与 UID，不要求地址相同，一个绑通配地址、一个绑具体地址的两个 `SO_REUSEPORT` socket 可以共用端口；补丁返回 `EADDRINUSE`。
- TCP 不分发连接。Linux 里组内每个 listener 有自己的 accept 队列，新连接按哈希选一个成员。补丁只让多个表项并存，没有改收包与 `accept` 的查找：两处都按端点取第一个匹配的表项，组内所有 socket 实际共用第一个表项的队列与 backlog，其余表项是空的。
- 关闭一个成员会丢掉整组排队的连接。`unlisten` 同样按端点删第一个匹配的表项，并销毁其中尚未 `accept` 的连接。不论关闭的是哪个成员，删掉的都是排着连接的那个表项。Linux 关闭 listener 只清它自己的队列。
- UDP 组内数据报的分发补丁没有涉及，diff 在 UDP 一侧只改了绑定登记。组内有多个成员时数据报实际落到哪一个没有核对，待核实。Linux 按哈希选成员。
- UDP 上 `SO_REUSEADDR` 不再起作用，见「溯源复核」。
- 非 inet 套接字。Linux 对非 inet 套接字置位返回 `EOPNOTSUPP`。补丁没有按协议族区分：以 AF_UNIX 流套接字为例，`set_option_inner` 先把选项交给 `GeneralOptions`（当前 dev 的 `unix/stream.rs` 第 292 行），后者照常保存。这一条是按代码路径读出来的，没有实测。

当前 dev：代码位置与合入时相同。`net/ax-net/src/general.rs` 第 115 行 `reuse_port()`；`tcp.rs` 第 507 至 509 行是 `bind` 里的预检查，第 1095 行 `TcpBoundEntry`，第 1108 行 `register_tcp_bound`，第 1130 行 `unregister_tcp_bound`；`listen_table.rs` 第 148 行 `listen`，第 176 行 `unlisten`，第 236 行 `accept`，第 321 行 `incoming_tcp_packet`；`wrapper.rs` 第 88 行 `udp_bind`，第 147 行 `udp_binds_conflict`；`udp.rs` 第 288 行；`os/StarryOS/kernel/src/syscall/net/opt.rs` 第 360 行。上面列的差异在当前 dev 上都还在。

## 溯源复核

- 提交归属。本 PR 的合并提交 [`e830bb282`](https://github.com/rcore-os/tgoskits/commit/e830bb2824aa5c7ba843c161ec3c8235e5956c2c) 改动 0 个文件。同一份内核改动随 #1502 的提交 [`1e3134198`](https://github.com/rcore-os/tgoskits/commit/1e31341986f21d74cabd286d31acdb50098112b8) 先 80 秒进入 dev，两个提交的树对象相同。两个 PR 的 diff 在这 10 个文件上逐字节相同。
- 有效 UID。Linux 在 TCP 的绑定冲突判断、UDP 的端口占用判断、加入 reuseport 组三处都要求 `uid_eq(uid, sk_uid(sk2))`，man 的说法是为了防止端口劫持。补丁的三张表里都没有 UID 字段。任何进程只要设了 `SO_REUSEPORT`，就能绑到另一个用户的 `SO_REUSEPORT` 端口上，并从共用的队列里 `accept` 走连接。
- 「reuseport 组」的含义比 Linux 窄。代码注释与测试名都写「mirroring Linux's reuseport group semantics」。相同的是「双方都设了选项才能共享、普通绑定不能加入」；不同的是上文列的地址、分发、关闭三点。`general.rs` 里 `reuse_port()` 的文档注释还留着早期版本的说法（「port reuse degrades to the same rebind allowance as SO_REUSEADDR」），与合入的实现不符，当前 dev 上仍在。
- UDP 的 `SO_REUSEADDR`。补丁之前 `UdpSocket::bind` 的条件是 `!self.general.reuse_address() && udp_bind(...)` 失败才报错，设了 `SO_REUSEADDR` 的 socket 根本不登记，也不受已有登记约束，比 Linux 宽。补丁删掉这个条件后，`SO_REUSEADDR` 在 UDP 绑定上完全不起作用，比 Linux 严：Linux 上两个都设了 `SO_REUSEADDR` 的 UDP socket 可以绑同一地址端口（`udp_lib_lport_inuse()` 里双方都有 `sk_reuse` 时不算占用），补丁之后第二个得到 `EADDRINUSE`。PR 正文没有提这处行为变化，回归用例也没有覆盖。当前 dev 上除了 `getsockopt` 读回之外，`reuse_address()` 只在 TCP 的 `bind` 里用到（`tcp.rs` 第 507 行），UDP 仍是这样。
- 正文与 diff。正文「改动」一节只写了 `register_tcp_bound` 与 `udp_bind`，「回归测」一节只写了绑定的三组断言。合入的 diff 还改了 `listen_table.rs`，用例里还有两组 `bind` 加 `listen` 的断言，都是评审指出「只放开了 `bind`，第二个 listener 的 `listen()` 仍失败」之后加的。正文说两张表「引用计数」，实现是每个绑定者一条记录的列表。
- 测试覆盖。系统用例止于 `bind()` 与 `listen()` 的返回值，没有向共享端口发起连接，没有从第二个 listener `accept`，没有关闭其中一个成员之后的行为，也没有通配地址与具体地址混用、不同 UID 的情形。上文的分发与关闭两点差异因此没有被用例触及。

## man 原文

[socket(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/socket.7?h=man-pages-6.19#n887)：

> SO_REUSEPORT (since Linux 3.9) Permits multiple AF_INET or AF_INET6 sockets to be bound to an identical socket address. This option must be set on each socket (including the first socket) prior to calling bind(2) on the socket. To prevent port hijacking, all of the processes binding to the same address must have the same effective UID. This option can be employed with both TCP and UDP sockets.

[socket(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/socket.7?h=man-pages-6.19#n902)：

> For TCP sockets, this option allows accept(2) load distribution in a multi-threaded server to be improved by using a distinct listener socket for each thread. This provides improved load distribution as compared to traditional techniques such using a single accept(2)ing thread that distributes connections, or having multiple threads that compete to accept(2) from the same socket.

[socket(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/socket.7?h=man-pages-6.19#n914)：

> For UDP sockets, the use of this option can provide better distribution of incoming datagrams to multiple processes (or threads) as compared to the traditional technique of having multiple processes compete to receive datagrams on the same socket.

[socket(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/socket.7?h=man-pages-6.19#n870)：

> SO_REUSEADDR Indicates that the rules used in validating addresses supplied in a bind(2) call should allow reuse of local addresses. For AF_INET sockets this means that a socket may bind, except when there is an active listening socket bound to the address. When the listening socket is bound to INADDR_ANY with a specific port then it is not possible to bind to this port for any local address. Argument is an integer boolean flag.

补丁之后的行为相当于 man 描述的「multiple threads that compete to accept(2) from the same socket」，只是这些线程各持一个 fd。

## 验证

- `syscall-test-so-reuseport`：选项默认值为 0，置 1、清 0 后 `getsockopt` 读回一致；两个设了 `SO_REUSEPORT` 的 TCP socket 绑同一 `127.0.0.1` 端口成功，第三个未设的得 `EADDRINUSE`；两个都未设的 TCP socket 第二个得 `EADDRINUSE`；两个设了选项的 TCP socket 先后 `bind()`、`listen()` 都成功，第三个未设的 `bind()` 得 `EADDRINUSE`；普通 listener 占住端口后，设了选项的 socket `bind()` 得 `EADDRINUSE`；UDP 上同样测了「两个设了选项的共享绑定、第三个未设的被拒」与「两个都未设的第二个被拒」。
