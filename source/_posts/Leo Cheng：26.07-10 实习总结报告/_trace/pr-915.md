## 问题与原因

psutil（以及基于它的 glances 等监控工具）在 StarryOS 上遍历进程即崩溃，两步：

1. `Process.num_threads()` 读 `/proc/<pid>/status`，用正则 `Threads:\t(\d+)` 取值后直接取第 0 个。StarryOS 的 `status` 没有 `Threads:` 行，匹配为空，抛 `IndexError`；psutil 的 `as_dict` 不吞这个异常。
2. 补上之后，`memory_info()` 打开 `/proc/<pid>/statm`，StarryOS 没有这个文件，抛 `FileNotFoundError`。

## 改动与影响范围

| 修改点 | 内容 |
|:--:|:--:|
| `render_task_status_fields` | 增加 `Threads:\t<n>`，`n` 取进程线程数 |
| `render_thread_statm` | 新增 `/proc/<pid>/statm`：`size` 为各映射区长度之和；`text`、`data` 按可执行、可写标志统计；`shared`、`lib`、`dt` 填 0；`resident` 暂填与 `size` 相同的值 |
| 目录项 | 进程目录与线程目录都列出 `statm` |
| 单元测试 | 断言 `Threads:` 行以制表符分隔 |

影响范围：只增加 procfs 输出，不改变已有字段。

与 Linux 的差异：`resident` 在 Linux 中是文件页、共享内存页与匿名页的驻留数之和，本拉取请求用虚拟大小作上界代替，`shared` 也填 0。这一差异后来已消除：当前 dev 的 `render_thread_statm` 改由 `ProcessMemStats::collect(..).format_statm()` 生成，`/proc/<pid>/stat` 同样取 `rss_pages()`。

### `statm` 的七个字段

合入前没有 `/proc/<pid>/statm` 这个文件。

Linux（[fs/proc/task_mmu.c#L94-L105](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/fs/proc/task_mmu.c#L94-L105)，各字段的来源）：

```c
unsigned long task_statm(struct mm_struct *mm,
			 unsigned long *shared, unsigned long *text,
			 unsigned long *data, unsigned long *resident)
{
	*shared = get_mm_counter_sum(mm, MM_FILEPAGES) +
			get_mm_counter_sum(mm, MM_SHMEMPAGES);
	*text = (PAGE_ALIGN(mm->end_code) - (mm->start_code & PAGE_MASK))
								>> PAGE_SHIFT;
	*data = mm->data_vm + mm->stack_vm;
	*resident = *shared + get_mm_counter_sum(mm, MM_ANONPAGES);
	return mm->total_vm;
}
```

Linux（[fs/proc/array.c#L698-L705](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/fs/proc/array.c#L698-L705)，输出顺序）：

```c
		seq_put_decimal_ull(m, "", size);
		seq_put_decimal_ull(m, " ", resident);
		seq_put_decimal_ull(m, " ", shared);
		seq_put_decimal_ull(m, " ", text);
		seq_put_decimal_ull(m, " ", 0);
		seq_put_decimal_ull(m, " ", data);
		seq_put_decimal_ull(m, " ", 0);
		seq_putc(m, '\n');
```

本 PR（`os/StarryOS/kernel/src/pseudofs/proc.rs` 的 `render_thread_statm`，第二个字段填的是 `size_pages`，第三个字段填 0）：

```rust
let mut size_pages: u64 = 0;
let mut text_pages: u64 = 0;
let mut data_pages: u64 = 0;
for area in mm.areas() {
    let pages = (area.size() / PAGE_SIZE_4K) as u64;
    size_pages += pages;
    let flags = area.flags();
    if flags.contains(MappingFlags::EXECUTE) {
        text_pages += pages;
    } else if flags.contains(MappingFlags::WRITE) {
        data_pages += pages;
    }
}

// size resident shared text lib data dirty
Ok(format!(
    "{size_pages} {size_pages} 0 {text_pages} 0 {data_pages} 0\n"
))
```

当前 dev（`os/StarryOS/kernel/src/mm/stats.rs`，06.08 合入的 #1171 把上面的函数体换成 `ProcessMemStats::collect(..).format_statm()`，以下是当前的 `format_statm`）：

```rust
pub fn format_statm(&self) -> String {
    let shared_rss = self.rss_file_pages + self.rss_shmem_pages;
    format!(
        "{} {} {} {} 0 {} 0\n",
        self.vss_pages,
        self.resident_pages,
        shared_rss,
        self.text_pages,
        self.data_pages.saturating_add(self.stack_pages),
    )
}
```

## man 原文

[proc_pid_status(5)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man5/proc_pid_status.5?h=man-pages-6.19#n284)：

> Threads Number of threads in process containing this thread.

[proc_pid_statm(5)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man5/proc_pid_statm.5?h=man-pages-6.19#n18)：

> size (1) total program size
> resident (2) resident set size
> shared (3) number of resident shared pages
> text (4) text (code)
> lib (5) library (unused since Linux 2.6; always 0)
> data (6) data + stack
> dt (7) dirty pages (unused since Linux 2.6; always 0)
