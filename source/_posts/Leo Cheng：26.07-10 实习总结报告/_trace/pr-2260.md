## 问题与原因

`do_select` 对每个 fd 取一次 `poll()` 的结果，再分别判断它在读、写、异常三个集合里是否就绪。补丁之前，读与写两个方向用的是同一个附加条件：`always_report = events & IoEvents::ALWAYS_POLL`，其中 `ALWAYS_POLL` 是 `ERR | HUP`。写方向的判定是 `selected.contains(OUT) || (write_set 含该 fd && always_report 非空)`，于是只带 `HUP` 的 fd 也被报告为可写。

典型场景是写端已关闭的管道读端：`poll()` 给出 `HUP`，把它放进 `writefds` 调 `select`，调用立即返回 1 且 `FD_ISSET` 为真。程序据此会去写一个只读的 fd。问题由 issue #2217 报告。

Linux 的 `select` 用三个掩码把 `poll` 事件映射到三个集合：读集合的掩码含 `EPOLLHUP` 与 `EPOLLERR`，写集合的掩码只含 `EPOLLERR`，不含 `EPOLLHUP`。

## 改动与影响范围

`do_select` 的就绪判定里新增 `write_report = events & IoEvents::ERR`，写方向的附加条件由 `always_report` 换成 `write_report`。读方向仍用 `always_report`（`ERR | HUP`），异常方向没有改。

影响范围：`select` 与 `pselect6`（都走 `do_select`）的写集合结果。`poll`、`ppoll`、`epoll` 不受影响，它们各自处理 `ALWAYS_POLL`。

当前 dev：代码仍在 `syscall/io_mpx/select.rs`，`write_report` 在第 153 行，写方向判定在第 157、158 行；`do_select` 起于第 56 行，`sys_select` 与 `sys_pselect6` 在第 222、256 行。`ALWAYS_POLL` 定义在 `components/axpoll/src/lib.rs` 第 45 行。

## 溯源复核

- 异常集合的映射与 Linux 不同，补丁没有涉及。Linux 的 `POLLEX_SET` 是 `EPOLLPRI | EPOLLNVAL`，`EPOLLERR` 不会让 fd 进入 `exceptfds`。`do_select` 把 `exceptfds` 里的 fd 登记为关心 `IoEvents::ERR`，判定是 `selected.contains(IoEvents::ERR) && except_set 含该 fd`：出错的 fd 在 StarryOS 上会出现在 `exceptfds` 里，在 Linux 上不会；带外数据这类 `POLLPRI` 事件在 Linux 上进入 `exceptfds`，在 StarryOS 上不会。当前 dev 未改（第 127、159、160 行）。
- PR 正文与用例注释把依据写成「Linux v7.2 `fs/select.c`」。本文按固定版本（7.1.0）核对，三个掩码的定义与正文所述一致。

## Linux 依据

- 三个掩码的定义：`POLLIN_SET` 含 `EPOLLHUP | EPOLLERR`，`POLLOUT_SET` 含 `EPOLLERR`、不含 `EPOLLHUP`，`POLLEX_SET` 是 `EPOLLPRI | EPOLLNVAL`：[fs/select.c#L459-L463](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/fs/select.c#L459-L463)
- `do_select` 按这三个掩码把 `poll` 结果分到三个结果集：[fs/select.c#L538-L552](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/fs/select.c#L538-L552)
- `pipe_poll`：读端在没有写者时得到 `EPOLLHUP`，`EPOLLOUT` 只在以写方式打开的 fd 上产生：[fs/pipe.c#L688-L704](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/fs/pipe.c#L688-L704)

## man 原文

[select(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/select.2?h=man-pages-6.19#n158)：

> writefds The file descriptors in this set are watched to see if they are ready for writing. A file descriptor is ready for writing if a write operation will not block. However, even if a file descriptor indicates as writable, a large write may still block.

[select(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/select.2?h=man-pages-6.19#n145)：

> The file descriptors in this set are watched to see if they are ready for reading. A file descriptor is ready for reading if a read operation will not block; in particular, a file descriptor is also ready on end-of-file.

[select(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/select.2?h=man-pages-6.19#n519)：

> we find the following definitions which show the correspondence between the readable, writable, and exceptional condition notifications of select() and the event notifications provided by poll(2) and epoll(7):

> #define POLLIN_SET  (EPOLLRDNORM | EPOLLRDBAND | EPOLLIN | EPOLLHUP | EPOLLERR) /* Ready for reading */ #define POLLOUT_SET (EPOLLWRBAND | EPOLLWRNORM | EPOLLOUT | EPOLLERR) /* Ready for writing */ #define POLLEX_SET  (EPOLLPRI) /* Exceptional condition */

[select(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/select.2?h=man-pages-6.19#n172)：

> exceptfds The file descriptors in this set are watched for "exceptional conditions". For examples of some exceptional conditions, see the discussion of POLLPRI in poll(2).
