## 问题与原因

OpenJDK 的 `NetworkInterface.getNetworkInterfaces()`（`enumIPv4Interfaces`）在 StarryOS 上枚举不到任何网卡，两处原因：

1. `SIOCGIFCONF` 的探测调用（`ifc_buf == NULL`）：Linux 返回容纳全部接口地址所需的字节数，调用方据此分配缓冲区；StarryOS 在这一分支返回 0，OpenJDK 分配 0 字节后认为没有网卡。
2. `SIOCGIFINDEX`（按名字查接口序号）没有实现，后续按序号的查询都失败。

## 改动与影响范围

| 修改点 | 内容 |
|:--:|:--:|
| `write_eth0_ifconf` 空缓冲分支 | 返回 `2 * IFREQ_COMPAT_LEN`，与缓冲非空时实际填入的条目数（eth0、lo 各一项）一致 |
| `SIOCGIFINDEX` | 新增，eth0 为 2、lo 为 1，与包套接字层的序号一致，经已有的 `write_ifreq_data` 写回 |
| `LO_IFINDEX` | 在 `packet.rs` 公开回环接口序号常量供复用 |

影响范围：套接字上的这两个 ioctl。纯增量，不改 TCP 与套接字数据路径。

当前 dev 保留 `SIOCGIFINDEX`（`file/net.rs` 第 495 行起），接口表后来已由 `NetInterface` 统一管理。

## Linux 依据

- `dev_ifconf()`：用户缓冲为空时对每个接口调用 `inet_gifconf(dev, NULL, 0, size)` 只累加长度，最后把总长度写回 `ifc_len`：[net/core/dev_ioctl.c#L40-L85](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/core/dev_ioctl.c#L40-L85)
- `SIOCGIFINDEX` 直接返回 `dev->ifindex`：[net/core/dev_ioctl.c#L169-L170](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/core/dev_ioctl.c#L169-L170)

## man 原文

[netdevice(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/netdevice.7?h=man-pages-6.19#n89)：

> SIOCGIFINDEX Retrieve the interface index of the interface into ifr_ifindex.

[netdevice(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/netdevice.7?h=man-pages-6.19#n309)：

> SIOCGIFCONF Return a list of interface (network layer) addresses. This currently means only addresses of the AF_INET (IPv4) family for compatibility. … If ifc_req is NULL, SIOCGIFCONF returns the necessary buffer size in bytes for receiving all available addresses in ifc_len.
