## 问题与原因

补丁之前 `handle_syscall` 没有 `mq_open`、`mq_unlink`、`mq_timedsend`、`mq_timedreceive`、`mq_notify`、`mq_getsetattr` 的分支，六个调用都落到 `Unimplemented syscall` 分支；内核里也没有队列对象、名字注册表和 `/dev/mqueue`。glibc 与 musl 的 `mq_open(3)`、`mq_send(3)`、`mq_receive(3)`、`mq_notify(3)`、`mq_getattr(3)`、`mq_setattr(3)`、`mq_unlink(3)` 全部建立在这六个系统调用上，所有用 POSIX 消息队列的程序都不能运行。

## 改动与影响范围

队列对象、名字注册表与限额放在新模块 `kernel/src/ipc/mqueue.rs`，系统调用入口在 `syscall/ipc/mqueue.rs`，`/dev/mqueue` 在 `pseudofs/mqueue.rs`。

| 系统调用 | 合入的行为 |
|:--:|:--:|
| `mq_open` | 名字在全局表 `MQ_REGISTRY` 里查找。已存在：`O_CREAT\|O_EXCL` 返回 `EEXIST`，访问模式为 `O_RDWR\|O_WRONLY` 返回 `EINVAL`，再按属主、组（含附加组）、其他三档检查读写位，缺位返回 `EACCES`，持 `CAP_DAC_OVERRIDE` 跳过。不存在：无 `O_CREAT` 返回 `ENOENT`；存活队列数达到 `queues_max` 且无 `CAP_SYS_RESOURCE` 返回 `ENOSPC`；`attr` 为空时取 `min(msg_max, msg_default)` 与 `min(msgsize_max, msgsize_default)`，否则两个字段须大于 0 且不超过上限（无特权取 `msg_max`、`msgsize_max`，有 `CAP_SYS_RESOURCE` 取 65536 与 16MiB），越界返回 `EINVAL`，乘积溢出返回 `EOVERFLOW`；按 `mq_bytes` 向创建者的 `RLIMIT_MSGQUEUE` 记账，超限返回 `EMFILE`；权限位取 `mode & ~umask & 0777`，属主取 `fsuid`、`fsgid`。描述符是 fd 表里的 `MqDescriptor`，默认带 close-on-exec；fd 分配失败时撤销本次新建的注册项，队列随引用归零而销毁并退还记账 |
| `mq_unlink` | 从注册表删除名字，已打开的描述符仍持有队列，最后一个引用释放时在 `Drop` 里减存活队列数并退还记账。调用者须是队列属主、`fsuid` 为 0 或持 `CAP_FOWNER`，否则返回 `EPERM`；名字不存在返回 `ENOENT` |
| `mq_timedsend` | 描述符以 `O_RDONLY` 打开返回 `EBADF`；优先级不小于 32768 返回 `EINVAL`；长度超过 `mq_msgsize` 返回 `EMSGSIZE`。队列满时：描述符带 `O_NONBLOCK` 返回 `EAGAIN`，否则阻塞到有空位、被信号打断或到达 `CLOCK_REALTIME` 绝对时限（`ETIMEDOUT`）。有空位时：若有接收者在等，消息直接放进排在最前的等待者的槽位，不入队也不触发通知；否则按优先级入队，并在队列由空变非空时触发通知 |
| `mq_timedreceive` | 描述符以 `O_WRONLY` 打开返回 `EBADF`；缓冲区小于 `mq_msgsize` 返回 `EMSGSIZE`。取最高优先级里最早的一条；取走后唤醒等待的发送者。队列空时：`O_NONBLOCK` 返回 `EAGAIN`，否则登记为等待者并阻塞。因超时、信号或非阻塞而退出前，在队列锁内再看一次自己的槽位，已被交接就按成功返回，否则把自己从等待者列表摘除 |
| `mq_notify` | 每个队列只有一个注册位，已被占用返回 `EBUSY`。`SIGEV_SIGNAL`：`sigev_signo` 大于 64 返回 `EINVAL`，等于 0 可以注册但不投递；触发时发 `si_code = SI_MESGQ` 的信号，`si_pid`、`si_uid` 是发送消息的进程，`si_value` 是注册时的 `sigev_value`。`SIGEV_NONE`：只占注册位。`SIGEV_THREAD`：`sigev_signo` 是 netlink 套接字的 fd，从 `sigev_value.sival_ptr` 读入 32 字节 cookie，触发时把末字节置为 `NOTIFY_WOKENUP` 后投到该套接字的接收队列。`sevp` 为空：只有注册者所在进程能清除，其余情况不做任何事并返回 0。通知触发一次后注册位清空 |
| `mq_getsetattr` | `mq_flags` 里有 `O_NONBLOCK` 以外的位返回 `EINVAL`。旧属性里的 `mq_flags` 取本描述符的 `O_NONBLOCK`，`mq_maxmsg`、`mq_msgsize`、`mq_curmsgs` 取队列。新属性只改本描述符的 `O_NONBLOCK`，同一队列的其他描述符不受影响 |

要点如下。

- 优先级：消息存在 `BTreeMap<u32, VecDeque<Message>>` 里，键是优先级。`pop_highest()` 取最大的键，再从该桶的队首取，得到「优先级从高到低、同优先级先进先出」。
- 阻塞：发送者与接收者各用一个 `PollSet`（`poll_send`、`poll_recv`）等待，经 `poll_io` 与 `timeout_at_wall` 实现非阻塞与绝对时限。等待的接收者另外登记在 `Inner::recv_waiters`，每个等待者有一个只在队列锁内读写的消息槽 `RecvWaiter::msg`，对应 Linux 的 `ext_wait_queue::msg` 与 `STATE_READY`。
- 通知：`send()` 只在「没有等待的接收者，且入队前队列为空」时取走注册并投递。描述符从 fd 表移除时清除本进程的注册：`FileLike` 新增 `on_close(owner)` 钩子，`release_locks_on_close` 统一调用它，覆盖 `close`、`close_range`、`dup2`/`dup3` 覆盖旧 fd、exec 时的 close-on-exec 与进程退出。
- 限额：`/proc/sys/fs/mqueue/` 下新增 `queues_max`、`msg_max`、`msgsize_max`、`msg_default`、`msgsize_default` 五个可读写文件，初值 256、10、8192、10、8192，写入范围分别是 0 至 `i32::MAX`、1 至 65536、128 至 16MiB、1 至 65536、128 至 16MiB，越界返回 `EINVAL`。`RLIMIT_MSGQUEUE` 的默认软硬上限设为 819200；每个队列记账 `maxmsg * 48 + min(maxmsg, 32768) * 48 + maxmsg * msgsize` 字节，48 是 64 位 Linux 上 `struct msg_msg` 与 `struct posix_msg_tree_node` 的大小。存活队列数用独立的原子计数，队列对象创建时加一、销毁时减一，名字被 `mq_unlink` 之后仍计入。
- `/dev/mqueue`：新伪文件系统（魔数 `0x19800202`），目录项由注册表即时生成，每个文件读出一行 `QSIZE`、`NOTIFY`、`SIGNO`、`NOTIFY_PID`；`stat` 报告队列的权限位、属主与时间，`st_size` 固定为 80。为此 `SimpleFile` 新增 `set_attrs` 与 `set_fixed_size`，`SimpleFsNode::metadata` 在存有非零大小时不再用内容长度覆盖。`fstat(mqd)` 走 `MessageQueue::kstat()`，同样报告 80。

其余改动：`starry-signal` 新增 `SI_MESGQ`（-3）与 `SignalInfo::new_mqueue`；`NetlinkSocket::deliver_datagram` 供 `SIGEV_THREAD` 投递 cookie；`Cred::has_cap_dac_override` 只是挪了位置。`syscall_allows_signal_restart` 的净改动只有一段注释：评审过程中一度把 `mq_timedsend`、`mq_timedreceive` 列为不可重启，被指出与 signal(7) 相反后撤回，合入后带 `SA_RESTART` 的处理函数返回时这两个调用会重启。

影响范围：六个新系统调用；所有 fd 关闭路径多一次 `on_close` 虚调用（除 `MqDescriptor` 外是空函数）；`getrlimit(RLIMIT_MSGQUEUE)` 的返回值；`SimpleFsNode` 上所有伪文件的 `metadata`（存储的大小为 0 时行为不变）。

合入时与 Linux 的差异：

- 名字：空名字与含 `/` 的名字都返回 `EINVAL`。Linux 对空名字在 `getname` 阶段返回 `ENOENT`，对含 `/` 的名字以及 `.`、`..` 在 `lookup_noperm_common()` 返回 `EACCES`；补丁不拒绝 `.` 与 `..`。
- 时间戳：`send()` 与 `receive()` 不更新队列的时间。Linux 在发送成功与从队列取走消息后都调用 `simple_inode_init_ts(inode)`，三个时间一起刷新；补丁里 `mtime` 自创建后不再变化，`atime`、`ctime` 只在注册或清除通知、`mq_setattr`、读 `/dev/mqueue` 文件时更新。
- 阻塞的发送者：没有等待者列表，接收者取走消息后只做唤醒，由被唤醒的发送者自己重新入队。Linux 由接收者在锁内替排在最前的发送者入队（`pipelined_receive`），这条路径不调用 `__do_notify`；补丁里被唤醒的发送者走普通入队路径，若此时队列为空且有注册，会触发一次 Linux 不会触发的通知（`mq_maxmsg` 为 1 时可达）。
- 等待者的次序：按登记先后。Linux 的 `wq_add()` 按任务优先级插入，同优先级先到先服务。
- 记账的用户：按创建者的 `fsuid` 记。Linux 记在 `cred->ucounts` 上，它以用户命名空间与实际用户 ID 为键。
- sysctl 写权限：在写入时检查 `CAP_SYS_RESOURCE`，不满足返回 `EPERM`。Linux 由 `mq_permissions()` 按有效用户 ID 是否为命名空间的 root 取 `0644` 的属主位，不满足时在权限检查处返回 `EACCES`，不看能力。
- 状态行：各字段不补空格，Linux 的格式串是 `QSIZE:%-10lu NOTIFY:%-5d SIGNO:%-5d NOTIFY_PID:%-6d`。对 mq 描述符调用 `read(2)` 不返回状态行，Linux 的 `mqueue_file_operations` 带 `.read`。
- `SIGEV_THREAD`：`sigev_signo` 指向的 fd 不是 netlink 套接字时一律返回 `EINVAL`，Linux 对非套接字返回 `ENOTSOCK`。投递信号前没有 `self_exec_id` 的比对。
- 打开已有队列时只认 `CAP_DAC_OVERRIDE`，Linux 对只读打开还认 `CAP_DAC_READ_SEARCH`。`attr` 只在创建分支里读取，Linux 只要指针非空就先拷入（[ipc/mqueue.c#L934-L935](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/ipc/mqueue.c#L934-L935)），坏指针即使不创建也返回 `EFAULT`。
- 没有 IPC 命名空间，注册表与五个可调值全局一份；`/dev/mqueue` 由内核在 `mount_all()` 里固定挂载。

## 溯源复核

- PR 正文的实现清单比合入的 diff 少。正文写的通知方式只有 `SIGEV_SIGNAL` 与 `SIGEV_NONE`，diff 还实现了经 netlink cookie 投递的 `SIGEV_THREAD`；正文也没有提 `RLIMIT_MSGQUEUE` 记账、`/proc/sys/fs/mqueue/` 五个文件、打开时的权限检查、`mq_unlink` 的属主检查与 `FileLike::on_close` 钩子。这些是 7 月 14 日至 22 日几轮评审中加进来的，记录在 PR 的评论里。
- 正文称队列名的处理「与 mqueuefs 语义一致」。名字的形状一致（去掉前导斜杠后的单段名），错误码不一致：Linux 对空名字返回 `ENOENT`、对含斜杠的名字返回 `EACCES`，mq_open(3) 也是这样写的，补丁两种情况都返回 `EINVAL`。当前 dev 未改。
- 正文称 `/dev/mqueue` 「按 Linux 列序报告」。列的次序一致，合入时列宽不一致，当前 dev 已按 Linux 的格式串补齐。
- `mq_sysctl_file` 的注释先写明 Linux 经 `mq_permissions` 只给属主 root 写位，随后称对应的能力是 `CAP_SYS_RESOURCE`。Linux 这条路径比较的是有效用户 ID，没有能力检查；补丁的判据与返回的错误码（`EPERM`）都与 Linux 不同。用例 `syscall-test-mq-blockers` 的 B3 断言的正是 `EPERM`。
- 「接收者在等时不触发通知」这一条经过三版才与 Linux 等价：最初用等待者计数 `blocked_receivers`，超时返回与计数恢复之间有窗口；第二版用延迟标志 `notify_owed`，接收者被调度前连续两次发送会丢通知；合入版改为把消息直接放进等待者的槽位并在锁内摘除等待者，与 `pipelined_send` 的做法一致。两次发送的时序由 `syscall-test-mq-blockers` 的 B1 覆盖。
- 发送与接收不刷新时间戳、阻塞发送者被唤醒后重新入队可能多触发一次通知，这两处差异在 PR 的评审中没有被提出，见上文差异列表。

## man 原文

[mq_overview(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/mq_overview.7?h=man-pages-6.19#n63)：

> Each message has an associated priority, and messages are always delivered to the receiving process highest priority first.

[mq_send(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_send.3?h=man-pages-6.19#n59)：

> Messages are placed on the queue in decreasing order of priority, with newer messages of the same priority being placed after older messages with the same priority.

[mq_send(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_send.3?h=man-pages-6.19#n66)：

> If the message queue is already full (i.e., the number of messages on the queue equals the queue's mq_maxmsg attribute), then, by default, mq_send() blocks until sufficient space becomes available to allow the message to be queued, or until the call is interrupted by a signal handler. If the O_NONBLOCK flag is enabled for the message queue description, then the call instead fails immediately with the error EAGAIN.

[mq_receive(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_receive.3?h=man-pages-6.19#n60)：

> If the queue is empty, then, by default, mq_receive() blocks until a message becomes available, or the call is interrupted by a signal handler. If the O_NONBLOCK flag is enabled for the message queue description, then the call instead fails immediately with the error EAGAIN.

[mq_notify(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_notify.3?h=man-pages-6.19#n92)：

> Message notification occurs only when a new message arrives and the queue was previously empty. If the queue was not empty at the time mq_notify() was called, then a notification will occur only after the queue is emptied and a new message arrives.
>
> If another process or thread is waiting to read a message from an empty queue using mq_receive(3), then any message notification registration is ignored: the message is delivered to the process or thread calling mq_receive(3), and the message notification registration remains in effect.
>
> Notification occurs once: after a notification is delivered, the notification registration is removed, and another process can register for message notification.

[mq_notify(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_notify.3?h=man-pages-6.19#n60)：

> The si_code field of the siginfo_t structure will be set to SI_MESGQ. In addition, si_pid will be set to the PID of the process that sent the message, and si_uid will be set to the real user ID of the sending process.

[mq_notify(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_notify.3?h=man-pages-6.19#n131)：

> EBUSY Another process has already registered to receive notification for this message queue.

[mq_getattr(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_getattr.3?h=man-pages-6.19#n85)：

> The only attribute that can be modified is the setting of the O_NONBLOCK flag in mq_flags. The other fields in newattr are ignored.

[mq_unlink(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_unlink.3?h=man-pages-6.19#n23)：

> The message queue name is removed immediately. The queue itself is destroyed once any other processes that have the queue open close their descriptors referring to the queue.

[mq_unlink(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_unlink.3?h=man-pages-6.19#n35)：

> EACCES The caller does not have permission to unlink this message queue.

手册写的是 `EACCES`；Linux 的粘滞位检查返回 `EPERM`（见上文 `fs/namei.c#L3705-L3708`），补丁与内核一致。

[mq_open(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_open.3?h=man-pages-6.19#n159)：

> EACCES name contained more than one slash.

[mq_open(3)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3/mq_open.3?h=man-pages-6.19#n239)：

> ENOENT name was just "/" followed by no other characters.

[mq_overview(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/mq_overview.7?h=man-pages-6.19#n258)：

> The RLIMIT_MSGQUEUE resource limit, which places a limit on the amount of space that can be consumed by all of the message queues belonging to a process's real user ID, is described in getrlimit(2).

[mq_overview(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/mq_overview.7?h=man-pages-6.19#n322)：

> On Linux, a message queue descriptor is actually a file descriptor. (POSIX does not require such an implementation.) This means that a message queue descriptor can be monitored using select(2), poll(2), or epoll(7). This is not portable.
>
> The close-on-exec flag (see open(2)) is automatically set on the file descriptor returned by mq_open(2).

[signal(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/signal.7?h=man-pages-6.19#n667)：

> If a blocked call to one of the following interfaces is interrupted by a signal handler, then the call is automatically restarted after the signal handler returns if the SA_RESTART flag was used; otherwise the call fails with the error EINTR:

[signal(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/signal.7?h=man-pages-6.19#n734)：

> POSIX message queue interfaces: mq_receive(3), mq_timedreceive(3), mq_send(3), and mq_timedsend(3).
