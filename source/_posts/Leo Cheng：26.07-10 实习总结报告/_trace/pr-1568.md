## 问题与原因

dnsmasq 内置的 TFTP 服务器在 StarryOS 上传不出文件，客户端超时。PR 正文给出两个原因。

- `setsockopt(IPPROTO_IP, IP_MTU_DISCOVER)` 返回 `ENOPROTOOPT`。`syscall/net/opt.rs` 的 `call_dispatch!` 表里没有 `(PROTO_IP, IP_MTU_DISCOVER)` 这一项。dnsmasq 在传输套接字 `bind()` 之后立刻设置这个选项，失败就放弃这次传输。
- UDP 数据报在 `sendto()` 之后立刻 `close()` 会丢。`sendto()` 只把数据报放进 smoltcp 套接字的发送缓冲并 `request_poll()` 唤醒轮询任务，真正的派发在之后；`UdpSocket::drop` 先 `shutdown` 再从 `SOCKET_SET` 移除，smoltcp 的 `close()` 丢弃发送缓冲，轮询任务还没运行，数据报就没了。dnsmasq 发完「文件未找到」的错误包后立刻关闭套接字，正好撞上。Linux 的 `udp_sendmsg()` 在不加塞（cork）时当场组包并交给 IP 层发出，关闭套接字时只清掉加塞中尚未发出的帧。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `GeneralOptions::ip_mtu_discover` | `net/ax-net/src/general.rs` | 新增 `AtomicU8` 字段，初值 `IP_PMTUDISC_WANT`（1）；`set_ip_mtu_discover()` 对大于 `IP_PMTUDISC_OMIT`（5）的值返回 `EINVAL`，否则保存；`get_option`、`set_option` 增加 `IpMtuDiscover` 分支 |
| `IpMtuDiscover(u8)` | `net/ax-net/src/options.rs` | 新增选项 |
| 分发 | `os/StarryOS/kernel/src/syscall/net/opt.rs` | `(PROTO_IP, IP_MTU_DISCOVER) => IpMtuDiscover as Int<u8>`；`Int<u8>` 用 `u8::try_from(i32)` 转换，负数与大于 255 的值也返回 `EINVAL` |
| `flush_egress()` | `net/ax-net/src/lib.rs` | 新增，同步调用 `poll_until_idle()` 把待发数据派发完 |
| `UdpSocket::drop` | `net/ax-net/src/udp.rs` | 在 `shutdown` 之前先调用 `flush_egress()` |

影响范围：所有使用 `GeneralOptions` 的套接字上的 `setsockopt`/`getsockopt(IPPROTO_IP, IP_MTU_DISCOVER)`；每个 UDP 套接字销毁时多一次同步轮询，发送缓冲为空时也会执行。

与 Linux 的差异：

- 选项只存取，不影响报文。Linux 上 `IP_PMTUDISC_DO` 会给所有出站包置 DF 位并对超过路径 MTU 的数据报返回 `EMSGSIZE`，`IP_PMTUDISC_DONT` 关闭路径 MTU 发现；补丁里各种模式的收发行为相同，代码注释写明 smoltcp 不建模路径 MTU 发现。
- 初值固定为 `IP_PMTUDISC_WANT`。Linux 在 `sysctl_ip_no_pmtu_disc` 非零时取 `IP_PMTUDISC_DONT`；StarryOS 没有这个 sysctl。
- 关闭前排空只加在 UDP 上。原始套接字的 `RawSocket::drop` 仍是 `shutdown` 后直接移除，同样的「发完即关」在原始套接字上没有处理。

当前 dev：`ip_mtu_discover` 在 `net/ax-net/src/general.rs` 第 54、89、145 至 157 行，`IpMtuDiscover(u8)` 在 `options.rs` 第 262 行，分发在 `os/StarryOS/kernel/src/syscall/net/opt.rs` 第 390 行。`flush_egress()` 仍在 `net/ax-net/src/lib.rs` 第 738 行，`UdpSocket::drop` 第 684 行仍先调用它；实现已随 ax-net 改为单一协议执行器而改写，不再调用 `poll_until_idle()`，改为向执行器登记一次请求并等它处理完。`RawSocket::drop`（`raw.rs` 第 645 行）仍没有排空。

## man 原文

[IP_MTU_DISCOVER(2const)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2const/IP_MTU_DISCOVER.2const?h=man-pages-6.19#n25)：

> Set or receive the Path MTU Discovery setting for a socket.

[IP_MTU_DISCOVER(2const)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2const/IP_MTU_DISCOVER.2const?h=man-pages-6.19#n33)：

> For non-SOCK_STREAM sockets, IP_PMTUDISC_DO forces the don't-fragment flag to be set on all outgoing packets. It is the user's responsibility to packetize the data in MTU-sized chunks and to do the retransmits if necessary. The kernel will reject (with EMSGSIZE) datagrams that are bigger than the known path MTU. IP_PMTUDISC_WANT will fragment a datagram if needed according to the path MTU, or will set the don't-fragment flag otherwise.

[IP_MTU_DISCOVER(2const)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2const/IP_MTU_DISCOVER.2const?h=man-pages-6.19#n47)：

> The system-wide default can be toggled between IP_PMTUDISC_WANT and IP_PMTUDISC_DONT by writing (respectively, zero and nonzero values) to the /proc/sys/net/ipv4/ip_no_pmtu_disc file.

[udp(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/udp.7?h=man-pages-6.19#n77)：

> By default, Linux UDP does path MTU (Maximum Transmission Unit) discovery. This means the kernel will keep track of the MTU to a specific target IP address and return EMSGSIZE when a UDP packet write exceeds it.

手册没有专门描述「发送后立刻关闭」的条文，这一条的依据是上面列出的 `udp_sendmsg()` 与 `udp_destroy_sock()` 源码。
