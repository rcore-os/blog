## 问题与原因

本 PR 将 #2416、#2417、#2418、#2425 的 tty/pty 修复并入 #2426，另补上会话首进程的 `setpgid` 规则。共同问题是 StarryOS 的终端状态与 Linux 的 session、PTY 两端和 PID namespace 语义没有保持一致：打开从端可能没有取得控制终端；PTY 从端关闭再打开后，master 仍观察到旧挂断；master 关闭后 `/dev/pts/N` 应消失，但只要从端仍打开，该 index 就不能复用；`tcgetpgrp`/`tcsetpgrp` 还必须使用调用者 PID namespace 可见的进程组编号。

此外，`setpgid` 允许修改 session leader 的进程组会破坏会话首进程必须保持自身 PGID 的规则；`/dev/tty` 在没有控制终端时也应返回 Linux 的 `ENXIO`。早期 C 回归用例有 fork 失败后误报通过及可能执行 `kill(-1, SIGKILL)` 的风险，合入前已修正测试失败分支。

## 改动与影响范围

改动集中在 StarryOS tty/pty 及其打开文件、作业控制路径：

| 行为 | 合并后的实现 |
|:--:|:--:|
| `setpgid` | 拒绝目标为 session leader 的请求，返回 `EPERM`。 |
| 打开 tty | 仅在控制终端绑定条件满足、打开模式允许读取且文件描述符成功分配后，才将 tty 设为控制终端；`O_NOCTTY`、write-only、pty master 和 `/dev/console` 不取得控制终端。 |
| `/dev/tty` | 当前进程没有控制终端时返回 `ENXIO`。 |
| PTY reopen/close | `PtyLink` 在同一锁下维护两端打开与 hangup 生命周期；从端重开清除对端的旧 hangup，master 关闭时移除 slave 路径，两端都关闭后才释放 index。 |
| tty 作业控制 ioctl | `tcgetpgrp` 返回调用者 PID namespace 可见的 PGID；`tcsetpgrp` 按该 namespace 解析传入 PGID。 |

用户可见范围包括 `setpgid(2)`、`open(2)`、`/dev/tty`、PTY 文件节点和 `TIOCGPGRP`/`TIOCSPGRP`。更改没有新增系统调用或扩展 ABI；它修正既有状态、错误码和名称空间映射。测试也补齐 fork 失败检查，避免把测试基础设施错误误判成内核行为通过。

- `setpgid()` 在定位目标并检查 session 关系后，遇到 `p->signal->leader` 返回 `-EPERM`：[kernel/sys.c#L1114-L1160](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/sys.c#L1114-L1160)

- 打开 `/dev/tty` 时，若当前进程没有 controlling tty，Linux 返回 `-ENXIO`：[drivers/tty/tty_io.c#L1867-L1877](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/tty_io.c#L1867-L1877)
- `tiocgpgrp()` 以 `pid_vnr()` 输出调用者可见的 PGID；`tiocspgrp()` 以 `find_vpid()` 在当前 PID namespace 解析输入：[drivers/tty/tty_jobctrl.c#L466-L478](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/tty_jobctrl.c#L466-L478)、[drivers/tty/tty_jobctrl.c#L493-L524](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/tty_jobctrl.c#L493-L524)
- `pty_close()` 标记对端关闭并唤醒其读写等待者；master 关闭时删除从端 devpts inode 并对从端执行 hangup：[drivers/tty/pty.c#L47-L75](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/pty.c#L47-L75)。从端重新打开时，`pty_open()` 清除 peer 的 `TTY_OTHER_CLOSED`：[drivers/tty/pty.c#L219-L233](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/pty.c#L219-L233)
- `devpts_pty_kill()` 负责移除 `/dev/pts/N` 节点：[fs/devpts/inode.c#L548-L562](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/fs/devpts/inode.c#L548-L562)；PTY index 则由 `pty_unix98_remove()` 在两端最终关闭、tty 被销毁时释放：[drivers/tty/pty.c#L702-L714](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/pty.c#L702-L714)

## man 原文

[`setpgid(2)`](https://man7.org/linux/man-pages/man2/setpgid.2.html) 将“修改 session leader 的 PGID”列为 `EPERM` 条件。 [`open(2)`](https://man7.org/linux/man-pages/man2/open.2.html) 对 `O_NOCTTY` 的说明是：终端不会成为进程的 controlling terminal。 [`tcgetpgrp(3)`](https://man7.org/linux/man-pages/man3/tcgetpgrp.3.html) 将其定义为返回该 terminal 的 foreground process group；[`pts(4)`](https://man7.org/linux/man-pages/man4/pts.4.html) 说明打开 `/dev/ptmx` 会创建对应的 `/dev/pts` slave。
