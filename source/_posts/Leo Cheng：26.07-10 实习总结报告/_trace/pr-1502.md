## 问题与原因

本 PR 的主体是两套应用测试。内核侧只有一件事：`SO_REUSEPORT`。

higress 的 README 写明 Envoy 在 Linux 上默认 `enable_reuse_port=true`，对每个 listener 都调用 `setsockopt(SO_REUSEPORT)`。补丁之前 `syscall/net/opt.rs` 的选项分发表里没有 `(SOL_SOCKET, SO_REUSEPORT)`，那一行是注释掉的 `TODO: needs kernel support`，调用落到兜底分支返回 `ENOPROTOOPT`，Envoy 创建 listener 失败。

`SO_REUSEPORT` 的内核实现另有独立的 [#1518](pr-1518.md)。本 PR 的分支为了能单独验证应用，把同一个内核提交一并带上，正文「Blocked-by」一节写明了这一点。

## 溯源复核

- 正文写「Blocked-by #1518」，实际合入顺序相反：本 PR 先合入并带入了全部内核改动，#1518 的合并提交是空提交。dev 上 `SO_REUSEPORT` 相关代码的提交归属是 #1502，查历史时要看这个提交。
- 应用侧对 `SO_REUSEPORT` 的验证只到「选项被接受」。`run-higress.sh` 的 `start_envoy` 固定带 `--concurrency 1`，`enable_reuse_port:true` 的那次启动只有一个 worker，每个端口只有一个 listener。多个 listener 共享端口只由 `syscall-test-so-reuseport` 覆盖，而该用例止于 `bind()` 与 `listen()` 的返回值，没有向共享端口发起连接，也没有从第二个 listener 上 `accept()`。
- 实现与 Linux 的差异在 [#1518](pr-1518.md) 的「溯源复核」里逐条列出，要点是：没有比较绑定者的有效 UID；只放行地址完全相同的绑定，Linux 不要求地址相同；TCP 组内所有连接进同一个队列，不按哈希分给各 listener；UDP 上 `SO_REUSEADDR` 在补丁之后不再起作用。

## man 原文

[socket(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/socket.7?h=man-pages-6.19#n887)：

> SO_REUSEPORT (since Linux 3.9) Permits multiple AF_INET or AF_INET6 sockets to be bound to an identical socket address. This option must be set on each socket (including the first socket) prior to calling bind(2) on the socket. To prevent port hijacking, all of the processes binding to the same address must have the same effective UID. This option can be employed with both TCP and UDP sockets.

## 验证

- 应用测试（PR 正文）：gateway 在 x86_64、aarch64、riscv64、loongarch64 上 `GATEWAY_OK=109/109`；higress 在 x86_64 与 aarch64 上 `HIGRESS_OK=65/65`，上游 Envoy 没有 riscv64 与 loongarch64 的发行版，这两个架构没有跑。
- `syscall-test-so-reuseport`：选项默认值为 0，置 1、清 0 后 `getsockopt` 读回一致；两个设了 `SO_REUSEPORT` 的 TCP socket 绑同一 `127.0.0.1` 端口成功，第三个未设的得 `EADDRINUSE`；两个都未设的 TCP socket 第二个得 `EADDRINUSE`；两个设了选项的 TCP socket 先后 `bind()`、`listen()` 都成功；普通 listener 占住端口后，设了选项的 socket `bind()` 得 `EADDRINUSE`；UDP 上同样测了「两个设了选项的共享绑定、第三个未设的被拒」与「两个都未设的第二个被拒」。
