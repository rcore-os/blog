## 问题与原因

busybox 的 `rdev` 在 StarryOS 上没有输出。它的做法是对 `/` 调 `stat` 取 `st_dev`，再遍历 `/dev`，找一个 `st_rdev` 与之相等的块设备节点，找到就打印 `<节点> /`。StarryOS 的 `/dev` 由 `pseudofs/dev` 的 `builder()` 静态构造，里面没有任何块设备节点的设备号等于根文件系统的 `st_dev`。根文件系统的 `st_dev` 是挂载时从 `DEVICE_COUNTER` 取的序号，根挂载是第一个，值为 1。

原先的 busybox 用例对 `rdev` 只要求不超时，这个缺口没有被测到。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `RootBlk` | `pseudofs/dev/mod.rs` | 新增设备类型，`read_at` 与 `write_at` 都返回 `AxError::Io`，标志为 `NON_CACHEABLE` |
| `/dev/vda` | 同文件的 `builder()` | 注册名为 `vda` 的 `NodeType::BlockDevice` 节点，设备号 `DeviceId::new(0, 1)`，后端是 `RootBlk` |
| busybox 用例 | `apps/starry/qemu/busybox/sh/busybox-tests.sh` | `rdev` 改为要求恰好一行 `/dev/<名字> /`；`fdflush`、`killall5`、`setlogcons`、`resize` 收紧判据；新增 `remove_shell` 及若干子用例 |

影响范围：`/dev` 下多出一个块设备节点。`stat` 得到块设备类型与设备号 0:1；`open` 成功；`read`、`write` 返回 `EIO`。遍历 `/dev` 找块设备的工具都会看到它。除此之外内核行为不变。

与 Linux 的差异：

- 设备号。Linux 里根文件系统若在块设备上，超级块的 `s_dev` 取自那个块设备，`stat("/")` 的 `st_dev` 与 `/dev` 节点的 `st_rdev` 因此相等，这是「文件系统挂在这个设备上」的结果。补丁是反过来凑的：根的 `st_dev` 是挂载序号 1，节点的设备号写死成同一个数。主设备号 0 在 Linux 里是 `UNNAMED_MAJOR`，只分给不在块设备上的文件系统（`get_anon_bdev()` 返回 `MKDEV(0, n)`），不会出现在块设备节点上。
- 打开语义。Linux 上块设备节点背后没有设备时，`open` 就返回 `ENXIO`。补丁的节点可以打开，读写时才返回 `EIO`。
- 名字写死为 `vda`，与根文件系统实际所在的设备无关。Linux 的 `vd` 前缀来自 virtio-blk 驱动，主设备号由 `register_blkdev(0, …)` 动态分配。

当前 dev：`RootBlk` 仍在 `pseudofs/dev/mod.rs` 第 169 行，节点注册在第 493 至 501 行。节点名不再写死，改取 `ax_fs_ng::root::root_block_identity().name`（`fs/ax-fs-ng/src/root.rs` 第 63 行，没有选定根设备时是 `blk0`）；设备号仍是 `DeviceId::new(0, 1)`，读写仍返回 `EIO`。`/proc/diskstats`（`pseudofs/proc.rs` 第 509 至 515 行）输出的是 `root_block_identity()` 里的主次设备号，它与节点的 0:1 是否一致没有核对，待核实。

## 溯源复核

- 这个节点在 Linux 上没有对应物。`rdev` 的匹配规则（`st_rdev == st_dev`）与 Linux 一致，但 0:1 这个设备号在 Linux 里表示匿名文件系统。根的 `st_dev` 主设备号为 0 时，Linux 上的 `rdev` 找不到匹配的块设备节点，不会有输出；补丁让 StarryOS 在同样的 `st_dev` 下输出 `/dev/vda /`。要与 Linux 一致，需要根文件系统的 `st_dev` 本身就是所在块设备的设备号，补丁没有动这一头。当前 dev 的设备号仍是 0:1。
- 节点成立依赖「根挂载是第一个挂载」。`DeviceId::new(0, 1)` 与 `DEVICE_COUNTER` 的初值 1 只是数值相等，两处没有共同的来源；挂载顺序一变，节点就不再匹配。回归用例断言了二者相等，能在这种情况下报错。
- PR 正文只写了六个 applet 的用例。合入的 diff 在 `busybox-tests.sh` 里还有九个新增子用例：`fdflush_noarg`、`fdflush_devnull`、`setlogcons_noarg`、`setlogcons_n1`、`resize_registered`、`resize_redir_stdin`、`remove_shell_multi`、`remove_shell_absent`、`remove_shell_noarg`。正文与评论里的 `PASS: 320  FAIL: 0` 没有随之更新。
- 回归用例断言 `open` 成功且 `read` 返回 `EIO`，这是占位节点自己的约定，Linux 上没有设备的块节点在 `open` 时就失败。

## man 原文

man-pages 6.19 没有 `rdev` 的条目。两个字段的含义见 [stat(3type)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3type/stat.3type?h=man-pages-6.19#n61)：

> .st_dev This field describes the device on which this file resides. (The major(3) and minor(3) macros may be useful to decompose the device ID in this field.)

[stat(3type)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man3type/stat.3type?h=man-pages-6.19#n105)：

> .st_rdev This field describes the device that this file (inode) represents.
