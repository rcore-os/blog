## 问题与原因

`shmctl` 的 `IPC_STAT` 与 `SHM_STAT` 把内核里的 `ShmidDs` 整个拷到用户缓冲区（前者经 `UserPtr` 整体赋值，后者是 `ptr.vm_write(guard.shmid_ds)`）。这个 `#[repr(C)]` 结构的最后一个字段是 `shm_nattch: c_ushort`，其后没有别的字段，整个结构为 `IpcPerm`（48 字节）加 48 字节。64 位架构上用户态看到的 `struct shmid64_ds` 里 `shm_nattch` 是 `unsigned long`，后面还有 `__unused4`、`__unused5` 两个 `unsigned long`，为 `ipc64_perm`（48 字节）加 64 字节。

`shm_nattch` 的偏移没有错，错的是宽度和总长度：内核只定义了低 2 个字节，随后 6 个字节是结构的尾部填充，内容未定义，用户态把这 8 个字节当成一个 `unsigned long` 读，高位可能是任意值；结构末尾的 16 个字节内核根本不写，用户缓冲区里保持调用前的内容。`IPC_SET` 方向同理，内核少读 16 个字节。受影响的是读取 `shmid_ds.shm_nattch` 的程序，PR 正文举的例子是 PostgreSQL、Oracle 与 MPI。

## 改动与影响范围

| 修改点 | 内容 |
|:--:|:--:|
| `ShmidDs::shm_nattch` | 类型由 `c_ushort` 改为 `__kernel_ulong_t` |
| `ShmidDs::__unused4`、`__unused5` | 新增两个 `__kernel_ulong_t` 保留字段，`ShmidDs::new` 里置 0 |
| 编译期断言 | `size_of::<ShmidDs>() == size_of::<IpcPerm>() + 64`，防止字段再被改窄或引入填充 |
| 导入 | 去掉不再使用的 `c_ushort` |

影响范围：`shmctl` 的 `IPC_STAT`、`SHM_STAT`（写出）与 `IPC_SET`（读入）所用的结构大小由 96 字节变为 112 字节；`shmat`、`shmdt` 对 `shm_nattch` 的增减改在 8 字节字段上进行，逻辑不变。

与 Linux 的差异：断言只约束 `IpcPerm` 之后的 64 字节，不检查各字段偏移，也不检查 `IpcPerm` 自身与 `ipc64_perm` 是否一致。合入时 `IPC_SET` 把用户传入的整个结构赋给内核里的 `shmid_ds`（`shm_inner.shmid_ds = *buf.get_as_mut()?`），`shm_nattch`、`shm_segsz` 等也被用户值覆盖，Linux 只取其中的权限字段；这是补丁之前就有的行为，补丁没有涉及。

当前 dev：结构移到 `os/StarryOS/kernel/src/ipc/shm.rs`，`ShmidDs` 在第 28 行，`shm_nattch`、`__unused4`、`__unused5` 在第 48 至 52 行，断言在第 58 至 61 行，内容未变。`IPC_SET` 已改为只更新权限字段（`syscall/ipc/shm.rs` 第 265 至 270 行）。

## 溯源复核

- PR 正文用 `test-shmctl-info` 全部通过作为验证，但这个用例不读 `shm_nattch`，也不检查结构大小：对 `SHM_STAT` 的结果只断言 `shm_segsz > 0`。它不触及本次修改的字段，不能证明这处修复。PR 没有新增用例，当前 dev 的测试目录里也搜不到读 `shm_nattch` 的断言。这处修复目前只有编译期的大小断言保护。
- 同一个用例，PR 正文报 101 PASS，评审者本地报 21 pass。用例对 `SHM_STAT` 按下标遍历，每个不存在的下标也计一条断言，条数随 `IPC_INFO` 返回的最大下标变化，两个数字不必相同；PR 里没有进一步说明。

- x86_64 直接包含通用定义，只有 x32 另行定义：[arch/x86/include/uapi/asm/shmbuf.h#L5-L7](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/arch/x86/include/uapi/asm/shmbuf.h#L5-L7)
- `struct ipc64_perm` 的布局：[include/uapi/asm-generic/ipcbuf.h#L22-L35](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/include/uapi/asm-generic/ipcbuf.h#L22-L35)
- `IPC_STAT`、`SHM_STAT` 先把整个 `shmid64_ds` 清零再填字段：[ipc/shm.c#L1084-L1090](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/ipc/shm.c#L1084-L1090)、[ipc/shm.c#L1144-L1146](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/ipc/shm.c#L1144-L1146)；随后按 `sizeof(struct shmid64_ds)` 整体拷给用户：[ipc/shm.c#L1274-L1283](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/ipc/shm.c#L1274-L1283)、[ipc/shm.c#L854-L858](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/ipc/shm.c#L854-L858)

## man 原文

[shmctl(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/shmctl.2?h=man-pages-6.19#n48)：

> shmatt_t        shm_nattch;  /* # of current attaches */

[shmctl(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/shmctl.2?h=man-pages-6.19#n93)：

> shm_nattch Number of processes that have this segment attached.

[shmctl(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/shmctl.2?h=man-pages-6.19#n145)：

> IPC_STAT Copy information from the kernel data structure associated with shmid into the shmid_ds structure pointed to by buf. The caller must have read permission on the shared memory segment.

man 只给出 `shmatt_t` 这个类型名，字段的实际宽度以上面的内核头文件为准。
