## 问题与原因

`UnixSocket::bind()` 和 `start_connect()` 原先在地址 `SpinLock` 仍持有时进入 `UnixNamespace`。pathname bind 要创建文件系统节点，connect 要解析路径；底层 VFS/ext4 会取得可睡眠锁，因此这些调用可能在禁止抢占的临界区阻塞。#2351 的 AArch64 SMP4 Flutter 合成器复现了 `sys_connect -> start_connect -> remote_addr SpinLock -> namespace resolve -> VFS lookup`，触发调度安全点检查；Firefox 的 Unix socket 连接路径也出现同类问题。

本 PR 的初衷是让可能睡眠的 namespace 调用离开地址自旋锁。第一版用“检查地址未设置后解锁，再进入 namespace，最后重新加锁写地址”的 pre-check 代替原来覆盖完整操作的锁，因此同时打开了新的并发窗口：重复 bind 可先后创建 pathname，后一个 transport bind 失败却未回滚节点；重复 connect 可向 seqpacket listener 投递两次请求并覆盖接收通道；连接 transport 已发布而 `remote_addr` 尚未发布时，查询者还可能观察到不一致状态。第二版加入 `binding`/`connecting` reservation 防止同一 socket 重入，但 pathname 失败清理和 transport/facade 状态原子发布仍未闭合，PR 最终关闭。

## 改动与影响范围

两次提交修改 `net/ax-net/src/unix/mod.rs`，试图用原子 `binding`/`connecting` 标记覆盖 namespace 回调窗口，把 `bind` 的地址检查、pathname 节点创建、transport bind 和地址发布拆成锁外调用及短临界区；`start_connect` 也先占 reservation，再解析 peer、调用 transport，最后发布 `remote_addr`。

修改触及 AF_UNIX pathname bind/connect、`getsockname`/`getpeername` 可观察地址，以及 seqpacket listener 的连接队列。它确实避免把原有自旋锁带入可能阻塞的文件系统路径，但跨临界区的 reservation 没有形成完整事务：bind 失败可能遗留 namespace 节点，connect 的 transport 状态和 facade 地址分阶段发布。PR 已关闭，不能将其描述为最终修复。后续由另一位作者的 [#2443](https://github.com/rcore-os/tgoskits/pull/2443) 将每 socket 地址锁改为可睡眠 `Mutex`，使检查、namespace/transport 调用与地址提交继续由同一把锁串行化；#2443 不属于本 README 按作者统计的我方 PR 范围。

## Linux 依据

- `unix_bind_bsd()` 先解析并创建 pathname 节点，再取得可睡眠的 `u->bindlock` 并检查 `u->addr`；若状态冲突或取得锁失败，跳到 `out_unlink` 撤销本次创建的节点：[net/unix/af_unix.c#L1350-L1412](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/unix/af_unix.c#L1350-L1412)
- `unix_stream_connect()` 先通过 `unix_find_other()` 查找 listener，然后在锁内检查 listener 状态、接收队列及客户端连接状态；它在取得客户端状态锁后再次验证 `sk_state`：[net/unix/af_unix.c#L1628-L1705](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/unix/af_unix.c#L1628-L1705)

Linux 也把可能进入 VFS 的 pathname 工作放在自旋锁之外，但不会用无锁 pre-check 假设状态仍未变化：bind 在 pathname 节点创建后用 per-socket mutex 串行检查并对失败节点做定向回滚；connect 则在 peer lookup 后锁定状态并重新验证。这支持“调用边界可睡眠、状态提交仍需同步”的判断，不支持把 reservation 标记本身视为已完成的事务。

## man 原文

[`unix(7)`](https://man7.org/linux/man-pages/man7/unix.7.html) 说明 pathname socket 通过 `bind(2)` 绑定文件系统路径，并指出绑定会在文件系统中创建 socket 节点，之后需由调用方 unlink。手册规定的是用户可见的地址和节点生命周期，不规定内核锁类型或锁顺序；并发顺序以固定版本的 `af_unix.c` 为依据。
