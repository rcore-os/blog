## 问题与原因

对内核采样时找到两处与请求大小无关的全量扫描。

`VmaMap` 是一棵按地址排序的 AVL 树，但 `lookup_range` 写成 `iter().filter(...)`：`iter()` 先把整棵树中序展开成 `Vec`，每个节点都动一次引用计数，然后才丢掉不相交的项。调用它的 `can_access_range` 挂在每一次用户内存访问的检查上，所以一次往用户态写一个 `timespec` 的 `clock_gettime` 也要展开整棵树。`munmap` 与 `mprotect` 里的两处循环写了「越过区间就 `break`」，同样省不下什么：`iter_entries()` 在循环取到第一项之前已经把整个向量建好。

`EpollInner::publish_ready_for_file` 是每次文件就绪回调都走的路径。它把这个 epoll 实例里的全部 interest 复制一份、排序，再遍历，只为找出与就绪文件是同一个文件的那几项，而这样的项通常只有一个。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| 区间访问 | `vma.rs` 的 `visit_overlapping`、`for_each_overlapping`、`for_each_overlapping_entry` | 沿树下降，只访问与区间相交的节点，回调返回 `false` 即停。VMA 互不重叠，所以左子树只在父节点起始晚于区间起始时才可能相交，右子树只在区间结束晚于父节点结束时才可能相交，不需要区间树的最大端点 |
| `lookup_range`、`contains_range` | `vma.rs` | 改在区间访问之上实现 |
| `can_access_range` | `aspace/mod.rs` | 直接用区间访问，不分配、不动不相交节点的引用计数 |
| `munmap` 收集待退役映射 | `aspace/mod.rs` 的 `prepare_retired_mapping_owners` | 只看区间内的 VMA；单个 VMA 的处理移到 `collect_retired_mapping_owner`，错误经一个 `Option` 带出闭包 |
| `mprotect` 的权限上限检查 | `aspace/mod.rs` | 只看区间内的 VMA |
| epoll 就绪回调 | `epoll.rs` 的 `snapshot_callback_batch`、`in_callback_batch` | 持 `interests` 锁时先按指针相等挑出回调命中的 interest 与同一文件上的别名，再排序、发布；指针比较不取第二把锁 |

影响范围：所有访问用户内存的系统调用（经 `can_access_range`）、`munmap`、`mprotect`，以及 epoll 的就绪通知。对外行为不变，只改代价。

当前 dev 上的状态分两部分。VMA 一侧原样保留，`visit_overlapping` 等三个函数与三条单测都在 `vma.rs`。epoll 一侧已被取代：09.21 合入的 #2456 把 `publish_ready_for_file` 换成 `publish_ready_interest`，回调只发布它命中的那一个 interest，`snapshot_callback_batch`、`in_callback_batch` 与对应的单测随之删除。

与 Linux 的差异：Linux 的 VMA 存在 maple tree 里，区间查找本来就只走搜索路径；访问用户内存时不查 VMA，靠页表与缺页处理。StarryOS 在用户内存访问的检查里仍会查 VMA，补丁把这次查找的代价从整棵树降到搜索路径。此外当前 dev 的 `aspace/mod.rs` 里仍有十二处 `iter_entries()` 的全量遍历没有改，`vma.rs` 里的寻找空闲区间与合并相邻 VMA 也还是全量遍历。

### VMA 区间查找

合入前（`os/StarryOS/kernel/src/mm/aspace/vma.rs`，`iter()` 先把整棵树展开成向量）：

```rust
pub fn lookup_range(&self, range: VirtAddrRange) -> Vec<Arc<VmaSnapshot>> {
    self.iter()
        .filter(|vma| vma.range.overlaps(range))
        .collect()
}
```

Linux（[mm/mmap.c#L884-L892](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/mm/mmap.c#L884-L892)）：

```c
struct vm_area_struct *find_vma_intersection(struct mm_struct *mm,
					     unsigned long start_addr,
					     unsigned long end_addr)
{
	unsigned long index = start_addr;

	mmap_assert_locked(mm);
	return mt_find(&mm->mm_mt, &index, end_addr - 1);
}
```

本 PR（同一文件，当前 dev 上仍是这段）：

```rust
fn visit_overlapping(
    node: &Option<Arc<VmaNode>>,
    range: VirtAddrRange,
    visited: &mut usize,
    visit: &mut impl FnMut(&Arc<VmaEntry>) -> bool,
) -> bool {
    let Some(current) = node else {
        return true;
    };
    *visited += 1;
    let vma = current.entry.snapshot.range;
    if range.start < vma.start
        && !Self::visit_overlapping(&current.left, range, visited, visit)
    {
        return false;
    }
    if vma.overlaps(range) && !visit(&current.entry) {
        return false;
    }
    if range.end > vma.end
        && !Self::visit_overlapping(&current.right, range, visited, visit)
    {
        return false;
    }
    true
}

pub fn lookup_range(&self, range: VirtAddrRange) -> Vec<Arc<VmaSnapshot>> {
    let mut found = Vec::new();
    self.for_each_overlapping(range, |vma| {
        found.push(vma.clone());
        true
    });
    found
}
```

fn publish_ready_interest(self: &Arc<Self>, interest: &Arc<EpollInterest>) {
    let published = {
        let interests = self.interests.lock();
        let is_current = interests
            .get(&interest.key)
            .is_some_and(|current| Arc::ptr_eq(current, interest));
        if !is_current || !interest.is_enabled() || !interest.try_mark_in_queue() {
            0
        } else {
            self.enqueue_marked_ready_without_wake(interest);
            1
        }

## 溯源复核

- PR 正文说 `can_access_range` 经 `UserAccess::prepare` 被每个访问用户内存的系统调用调用。当前 dev 上 `mm/access.rs` 的 `prepare` 确实调它，但前面有一步探测：页已在就直接返回，不查 VMA。这一步在本 PR 合入时是否已有，没有核对。
- epoll 一侧合入后只存在了十三天。#2456 的做法更直接，也更接近 Linux：回调只处理自己对应的那一项，不再找同一文件上的别名。
- 这个 PR 没有系统测试。行为不变这一点靠已有的 epoll 行为单测与 `qemu/syscall-test-epoll`、`qemu/syscall-test-mprotect-wx` 两个用例守住。
- 正文末尾写明变基之后 `cargo xtask clippy --package starry-kernel` 没有等到完整矩阵结束就推送了，那一轮不声明静态检查通过。
