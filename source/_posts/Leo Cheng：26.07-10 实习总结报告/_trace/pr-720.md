## 问题与原因

本 PR 叠在 [#719](pr-719.md) 之上，处理 `open(2)` 里要跨几个软件包才能改的五处行为，另加一个它们共用的错误码：

- 没有对应 `ENXIO` 的错误类型。`AxErrorKind` 里只有映射到 `ENODEV` 的 `NoSuchDevice`。
- 路径末尾的斜杠被丢掉。`Components` 解析时去掉末尾的空分量，`open("file/")` 于是当成 `open("file")` 成功。
- 对悬空符号链接用 `O_CREAT`：解析符号链接得到 `NotFound` 就直接返回，不在链接指向的位置创建文件。
- 打开文件系统上的 UNIX 套接字文件会成功，Linux 返回 `ENXIO`。
- 以 `O_WRONLY|O_NONBLOCK` 打开没有读端的 FIFO 会成功，Linux 返回 `ENXIO`。
- 对 `O_PATH` 得到的描述符调用 `fchmod` 会成功。目录的 `Directory` 对象不保存打开标志，内核认不出它是 `O_PATH` 打开的。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `ENXIO` | `axerrno` 的 `AxErrorKind::NoSuchDeviceOrAddress` | 新增一个错误类型，映射到 `ENXIO` |
| 末尾斜杠 | `axfs-ng-vfs` 的 `Path::has_trailing_slash`；`axfs-ng` 的 `OpenOptions::open` | 路径以 `/` 结尾时不再创建文件，解析结果不是目录则返回 `ENOTDIR`；同时带 `O_NOFOLLOW` 且末分量是符号链接时也是 `ENOTDIR`，先于 `ELOOP` |
| 悬空符号链接 | `OpenOptions::open` | 带 `O_CREAT`、末分量是符号链接且目标不存在时，以链接内容为新路径再打开一次，在目标位置创建 |

## 溯源复核

2026-09-29 用一个 32 项的探针程序在宿主 Linux 6.6 与 StarryOS（dev `05175ca3`，x86_64）上各跑一遍，28 项一致，4 项不同，都落在本 PR 改过的两处：

| 操作 | Linux | StarryOS |
|:--:|:--:|:--:|
| `O_CREAT` 打开不存在的 `new/` | `EISDIR` | `ENOENT` |
| `O_CREAT` 打开已存在的普通文件 `file/` | `EISDIR` | `ENOTDIR` |
| 对 `O_PATH` 描述符 `chmod("/proc/self/fd/<n>")` | 成功 | `EBADF` |
| 对 `O_PATH` 描述符 `fchmodat2(fd, "", AT_EMPTY_PATH)` | 成功 | `EBADF` |

- 末尾斜杠加 `O_CREAT`：Linux 在查找之前就返回 `EISDIR`，不管名字存在与否。补丁的做法是去掉创建标志再按「必须是目录」检查，所以给出 `ENOENT` 或 `ENOTDIR`。不带 `O_CREAT` 的情形两边一致。
- `O_PATH` 与 `fchmod`：Linux 只有 `fchmod(2)` 本身拒绝 `O_PATH` 描述符。`fchmodat` 与 `fchmodat2` 按路径解析到 inode 后修改，经 `/proc/self/fd/<n>` 或 `AT_EMPTY_PATH` 到达同一个 inode 时都成功。补丁里的注释说「Linux 的 procfs 会把 `O_PATH` 的限制沿符号链接传下去」，这个说法不成立。StarryOS 把 `fchmod(fd)` 实现成 `fchmodat(fd, NULL, mode, AT_EMPTY_PATH)`，所以区分不了 `fchmod` 与 `fchmodat2(AT_EMPTY_PATH)`。这两处判断当前 dev 上仍在。
- FIFO：补丁对所有非阻塞写打开都返回 `ENXIO`，有读端时也一样，与 Linux 不符。PR 正文写明这是只覆盖「没有读端」的保守版本，对应 issue #711 只算部分修复。当前 dev 的实现已经按读端计数。
- PR 正文的数字与 diff 不符。正文多处写「51 个文件、+1557/-38、20 个复现用例」，这是变基到 #719 之前、把 #719 的内容一并算进去的数。合入的 diff 是 21 个文件：7 个源码文件、5 个用例目录共 10 个文件、4 个 toml。正文里列出的修复点有不少属于 #719，例如 `resolve_at` 改用 `location()`。

## man 原文

> Obtain a file descriptor that can be used for two purposes: to indicate a location in the filesystem tree and to perform operations that act purely at the file descriptor level. The file itself is not opened, and other file operations (e.g., read(2), write(2), fchmod(2), fchown(2), fgetxattr(2), ioctl(2), mmap(2)) fail with the error EBADF.

[open(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/open.2?h=man-pages-6.19#n1203)：

> ENOTDIR A component used as a directory in path is not, in fact, a directory, or O_DIRECTORY was specified and path was not a directory.

> ENXIO O_NONBLOCK | O_WRONLY is set, the named file is a FIFO, and no process has the FIFO open for reading.

> ENXIO The file is a UNIX domain socket.
