## 问题与原因

StarryOS 没有 `/dev/net/tun`。PR 正文记录的基线结果是 `open("/dev/net/tun")` 返回 `ENOENT`。缺的不只是设备节点：ax-net 的 `InterfaceKind` 只有回环与以太网两种，没有由用户态充当链路的接口；套接字上的接口配置 ioctl 只有查询类，`SIOCSIFADDR`、`SIOCSIFNETMASK`、`SIOCSIFMTU`、`SIOCADDRT`、`SIOCDELRT` 都没有实现，`SIOCSIFFLAGS` 只接受与当前标志相同的值；VFS 的 direct 读写会循环调用设备直到填满或写完用户缓冲区，不保留「一次调用一帧」的记录边界。依赖 TUN/TAP 的用户态程序（隧道、用户态协议栈，以及仓库里等它合入的 dnsmasq TFTP 用例 #1536）因此不能运行。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `/dev/net/tun` 节点 | `pseudofs/dev/net/mod.rs` | 字符设备 (10, 200)，目录不缓存，每次 `open` 新建一个 `TunFile` |
| `TUNSETIFF` | `dev/net/tun.rs` 的 `set_iff`、`attach` | 文件已挂接返回 `EEXIST`。名字对应的接口已存在：带 `IFF_TUN_EXCL` 返回 `EBUSY`，类型不符返回 `EINVAL`，队列已被占用返回 `EBUSY`。不存在：无 `CAP_NET_ADMIN` 返回 `EPERM`，`IFF_TUN` 与 `IFF_TAP` 都没给返回 `EINVAL`，两者都给取 TUN。请求 `IFF_VNET_HDR`、`IFF_MULTI_QUEUE`、`IFF_NAPI`、`IFF_NAPI_FRAGS` 返回 `EINVAL`。挂接、`TUNSETPERSIST` 与关闭由全局锁 `TUN_CONTROL` 串行。名字写回用户态失败时返回 `EFAULT`，挂接保留 |
| `TUNGETIFF`、`TUNGETFEATURES`、`TUNSETPERSIST` | 同上 | `TUNGETIFF` 返回类型、挂接时请求的 `IFF_NO_PI`/`IFF_ONE_QUEUE`、`IFF_PERSIST` 与 `IFF_NOFILTER`；`TUNGETFEATURES` 返回 `IFF_TUN\|IFF_TAP\|IFF_NO_PI\|IFF_ONE_QUEUE`；`TUNSETPERSIST` 改设备级标志，不查能力。其余命令返回 `EINVAL` |
| `read` | `TunFile::read_at` | 一次取一帧，返回 `min(帧长, 缓冲区长度)`，队列空时设备返回 `WouldBlock`。带 PI 时先写 4 字节 `tun_pi`，缓冲区不足 4 字节返回 `EINVAL`（帧已出队），载荷被截断时置 `TUN_PKT_STRIP` |
| `write` | `TunFile::write_at` | 依次检查 PI 长度、TAP 的以太网头长度、无 PI 的 TUN 的 IP 版本（`EINVAL`），再检查接口是否 `IFF_UP`（`EIO`），通过后入队并返回整个缓冲区长度 |
| `poll` 与关闭 | 同上 | 未挂接返回 `POLLERR`；发往 fd 的队列非空可读；接口已拉起可写。关闭时释放队列，设备未设 `IFF_PERSIST` 就注销 |
| 队列与设备 | `ax-net/src/device/tun.rs` | `TunShared` 持有两个方向各 500 帧的队列、挂接状态（`Free`/`Attached`/`Dying`）、设备级 `IFF_PERSIST`、`IFF_UP` 与帧长上限。`TunDevice` 把裸 IP 包交给路由器；TAP 用 `TapPort` 实现 `EthernetFramePort`，复用 `EthernetDevice` 处理 ARP 与二层过滤并打开组播接收。队列满或帧超过 MTU 时丢弃并计 `tx_dropped`。接口由未拉起变为拉起时唤醒等待 `POLLOUT` 的写者 |
| 接口的创建与删除 | `ax-net/src/service.rs`、`lib.rs` | `create_tun` 校验名字（非空、短于 16 字节、不是 `.`/`..`、不含 `/`、`:` 与空白），空名取 `tun%d`/`tap%d`，`%d` 模板取第一个未用的序号；接口 id 单调递增不复用。TUN 带 `POINTOPOINT\|NOARP\|MULTICAST`，TAP 带 `BROADCAST\|MULTICAST` 与由接口 id 派生的本地管理 MAC。`remove_tun_interface` 同时清除地址、路由、DNS 与 DHCP 状态 |
| 路由器的设备槽 | `ax-net/src/router.rs` | 设备槽改为 `Option`，删除设备只清空槽位并从 `pending_fanout` 去掉该下标，其他接口的下标不变 |
| 以太网收发 | `ax-net/src/device/ethernet.rs`、`driver.rs` | 目的地址过滤抽成 `accepts_destination()`，新增默认关闭的 `accept_multicast`；新增 `NetDeviceError::Dropped`，端口丢帧时以太网层计丢包并返回 0 字节，数据帧、ARP 请求、ARP 应答与待发队列补发都按此处理 |
| 接口配置 ioctl | `kernel/src/file/net.rs` | 新增 `SIOCSIFMTU`、`SIOCSIFADDR`、`SIOCSIFNETMASK`、`SIOCADDRT`、`SIOCDELRT`，`SIOCSIFFLAGS` 可切换 TUN/TAP 的 `IFF_UP`，全部要求 `CAP_NET_ADMIN`。`SIOCSIFADDR` 在点到点接口上取 /32，其余按分类地址取前缀，D 类返回 `EINVAL`，全零地址只删除现有地址；`SIOCSIFNETMASK` 拒绝不连续的掩码。路由 ioctl 依次返回 `EAFNOSUPPORT`、`EINVAL`、`ENODEV`，经未拉起的设备加路由返回 `ENETDOWN`，删除不存在的路由返回 `ESRCH`。TUN 的 `SIOCGIFHWADDR` 为 `ARPHRD_NONE`，`SIOCGIFDSTADDR` 为本端地址，`SIOCGIFBRDADDR` 为 0 |
| rtnetlink | `kernel/src/file/netlink.rs` | TUN 的链路类型为 `ARPHRD_NONE`，带 `IFF_POINTOPOINT\|IFF_NOARP`，不输出 `IFLA_ADDRESS`、`IFLA_BROADCAST` 与 `IFA_BROADCAST`；TAP 与以太网相同 |
| 记录边界 | `axfs-ng-vfs` 的 `NodeFlags::PACKET`、`ax-fs-ng/src/file/handle.rs` | 带此标志的节点一次 `read` 只调用设备一次，一次 `write` 把整个用户缓冲区（上限 128KiB，超过返回 `EINVAL`）一次交给设备；空缓冲区的 `read` 不进入设备 |

影响范围：新节点 `/dev/net/tun` 及其上的 `ioctl`、`read`、`write`、`poll`、`close`；所有套接字上的接口配置 ioctl；rtnetlink 的链路与地址转储。对已有接口有两处可见变化：查询类 ioctl 在接口没有 IPv4 地址时由 `NoSuchDeviceOrAddress` 改为返回 `EADDRNOTAVAIL`；物理网卡的收帧过滤逻辑搬进了 `accepts_destination()`，放行条件未变（广播、全零、本机地址）。

评审中争议过的 Linux 行为与结论：

| 争议点 | Linux 的行为 | 结论 |
|:--:|:--:|:--:|
| `IFF_TAP` 最初仍按裸 IP 包收发 | TAP 读写以太网帧，`ether_setup()` 初始化 | 改为 `EthernetDevice` 加 `TapPort` |
| 未声明多队列时第二个 fd 也能挂接 | `tun_attach()` 返回 `EBUSY` | 照此实现 |
| `IFF_PERSIST` 存在 fd 上 | 存在设备的 `tun->flags` 上，最后一个队列关闭时才据此决定是否注销 | 移到 `TunShared::persist` |
| 带 PI 的短读不置标志 | `tun_put_user()` 在缓冲区小于总长时置 `TUN_PKT_STRIP` | 照此实现 |
| 空名固定取 `tun0`、`%d` 模板与非法名字 | 空名用 `tun%d`/`tap%d`，经 `dev_valid_name()` 与 `__dev_alloc_name()` | 照此实现 |
| TUN 的固有标志缺失 | `IFF_POINTOPOINT \| IFF_NOARP \| IFF_MULTICAST`，类型 `ARPHRD_NONE` | 照此实现 |
| 零长度 `read` 吞掉一帧 | `tun_do_read()` 对空 iov 直接返回 0，不取帧 | 去掉把长度钳到 1 的做法 |
| 接口未拉起时 `write` 成功 | `tun_get_user()` 返回 `EIO` | 照此实现，排在格式检查之后 |
| 点到点接口上 `SIOCSIFADDR` 固定取 /24 | 点到点取 /32，其余取分类前缀 | 照此实现 |
| 只等 `POLLOUT` 的线程在接口拉起后不被唤醒 | `tun_chr_poll()` 总是登记到等待队列；`NETDEV_UP` 时对每个队列调用 `sk_write_space()` | 按请求登记 IN 与 OUT，拉起时唤醒 OUT |
| 发往 TAP 的帧在队列满时仍计为已发送 | `tun_net_xmit()` 环满时计 `tx_dropped` 并返回 `NET_XMIT_DROP` | 丢帧返回 `Dropped`，不计入发送；不向上层报错 |
| `TUNSETPERSIST` 是否要查 `CAP_NET_ADMIN` | 该分支没有能力检查 | 不改 |
| 挂接已有设备是否要查能力 | 只调用 `tun_not_capable()`，设备未设 owner 与 group 时恒为假 | 不改；补丁没有实现 owner 与 group |
| 写回名字失败后是否回滚挂接 | `copy_to_user` 失败只把返回值改成 `EFAULT`，挂接保留 | 最终版保留挂接，删去中途加入的回滚路径与对应用例 |
| `SIOCSIFMTU` 只接受 1500 | 最小 68，最大 `65535 - hard_header_len` | 部分照办：接受 68 至 1500，见下文差异 |
| 物理网卡丢弃组播帧 | 不涉及 Linux 语义，评审认为是对现有网卡的回归 | 基线上的过滤条件本来如此，补丁未改变，只有 TAP 打开组播接收 |

与 Linux 的差异：

- 未挂接的文件上 `read`、`write` 与除 `TUNSETIFF`、`TUNGETFEATURES` 外的 ioctl 返回 `EBADF`，Linux 返回 `EBADFD`。
- MTU 只接受 68 至 1500。Linux 在 IP 层按 MTU 分片（[net/ipv4/ip_output.c#L308-L313](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/ipv4/ip_output.c#L308-L313)），`tun.c` 的收发路径里没有 MTU 检查；补丁在设备入队处丢弃超过 MTU 的出站帧。`SIOCSIFMTU` 与改变标志的 `SIOCSIFFLAGS` 只对 TUN/TAP 生效，对以太网与回环接口返回 `EOPNOTSUPP`。
- 用户态写入的帧超过标准帧长（1500 加链路头）或入站队列已满时被丢弃，`write` 仍返回完整长度。
- 不支持 `IFF_MULTI_QUEUE`、`IFF_VNET_HDR`、`IFF_NAPI`、`IFF_NAPI_FRAGS`，请求时返回 `EINVAL`；`TUNGETFEATURES` 也不列出它们与 `IFF_NO_CARRIER`。没有 `TUNSETOWNER`、`TUNSETGROUP`、`TUNSETQUEUE` 等其余 ioctl。
- `SIOCADDRT` 必须给出 `rt_dev`，且该接口已有 IPv4 地址；Linux 可以只凭网关推出设备。
- TAP 的 MAC 由接口 id 派生（`02:00` 加 4 字节 id），Linux 取随机地址。

## 溯源复核

- 逐条对照 PR 正文与合入的 diff：`TUNSETIFF` 的检查次序、`read`/`write` 的检查次序、`poll` 的三种状态、各 ioctl 的错误码都与正文一致，也与下文所列 Linux 行一致。正文「与 Linux 的差异」一节列了四条，diff 里另有两条没有列出：`SIOCSIFMTU` 与改变标志的 `SIOCSIFFLAGS` 对非 TUN/TAP 接口返回 `EOPNOTSUPP`；查询类 ioctl 的无地址错误码对所有接口改成了 `EADDRNOTAVAIL`（这一条与 Linux 的 `devinet_ioctl()` 一致，但改变了已有接口的返回值）。
- 最后一轮自动评审（9 月 28 日）指出 `TunShared` 的 `detached`、`is_attached`、`is_dying` 是公开方法却没有生产调用方，标为不阻塞。合入时未改，当前 dev 上仍在（`device/tun.rs` 第 116、152、156 行）。
- `SIOCSIFMTU` 的结论是折中。7 月 23 日与 29 日的评审要求 MTU 成为每接口可变状态并约束数据面；合入版做到了「设置值可读回、发往 fd 的帧不超过该值」，但上限停在 1500，Linux 的上限是 65535 减链路头。正文已写明这一差异。
- 「写回名字失败」这条路径反复过：7 月 22 日评审要求回滚，随后加入了回滚与注入用例，9 月 2 日评审指出用户态用例走不到该路径；合入版改回 Linux 的做法（保留挂接、不回滚），并删掉了那条用例。因此合入版里没有用例覆盖「写回失败后挂接仍在」，只有代码注释说明。
- 9 月 15 日五条行内意见里有三条（物理网卡组播、`TUNSETPERSIST` 的能力检查、挂接已有设备的能力检查）没有改代码。后两条的行内回复引用了 `drivers/net/tun.c` 的行（`#L3148-L3165`、`#L3119-L3121`、`#L2732`、`#L513-L521`），本文按同一版本核对过，行号与内容相符；组播一条引用的是基线上原有的过滤条件，可以从 diff 删除的那几行里看到。

## man 原文

man-pages 6.19 没有 tun 或 tap 的条目。内核文档 `Documentation/networking/tuntap.rst` 的对应原文如下。

[Documentation/networking/tuntap.rst#L27-L35](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/Documentation/networking/tuntap.rst#L27-L35)：

> In order to use the driver a program has to open /dev/net/tun and issue a corresponding ioctl() to register a network device with the kernel. A network device will appear as tunXX or tapXX, depending on the options chosen. When the program closes the file descriptor, the network device and all corresponding routes will disappear.
>
> Depending on the type of device chosen the userspace program has to read/write IP packets (with tun) or ethernet frames (with tap). Which one is being used depends on the flags given with the ioctl().

[Documentation/networking/tuntap.rst#L56-L58](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/Documentation/networking/tuntap.rst#L56-L58)：

> There's no harm in allowing the device to be accessible by non-root users, since CAP_NET_ADMIN is required for creating network devices or for connecting to network devices which aren't owned by the user in question.

[Documentation/networking/tuntap.rst#L85-L88](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/Documentation/networking/tuntap.rst#L85-L88)：

> ``char *dev`` should be the name of the device with a format string (e.g. "tun%d"), but (as far as I can see) this can be any valid network device name. Note that the character pointer becomes overwritten with the real device name (e.g. "tun0")::

[Documentation/networking/tuntap.rst#L123-L127](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/Documentation/networking/tuntap.rst#L123-L127)：

> If flag IFF_NO_PI is not set each frame format is::
>
>      Flags [2 bytes]
>      Proto [2 bytes]
>      Raw protocol(IP, IPv6, etc) frame.

接口配置 ioctl 见 [netdevice(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/netdevice.7?h=man-pages-6.19#n73)：

> If an ioctl is marked as privileged, then using it requires an effective user ID of 0 or the CAP_NET_ADMIN capability. If this is not the case, EPERM will be returned.

[netdevice(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/netdevice.7?h=man-pages-6.19#n232)：

> SIOCGIFMTU SIOCSIFMTU Get or set the MTU (Maximum Transfer Unit) of a device using ifr_mtu. Setting the MTU is a privileged operation.
