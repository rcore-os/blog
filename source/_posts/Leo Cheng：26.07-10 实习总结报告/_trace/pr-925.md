## 问题与原因

`check_signals` 把 `SignalOSAction::Stop` 处理成 `do_exit(1, true)`：进程收到 `SIGSTOP`、`SIGTSTP`、`SIGTTIN`、`SIGTTOU` 时被直接杀死而不是挂起；`SignalOSAction::Continue` 是空实现；父进程的 `waitpid(WUNTRACED/WCONTINUED)` 也得不到停止与继续的通知。shell 作业控制、`killall5 -STOP/-CONT` 以及依赖作业控制的 busybox 工具因此失效。根本缺的是一套作业控制状态：没有「已停止」标志，没有让停止的线程在内核里挂起、等 `SIGCONT` 或 `SIGKILL` 的机制，也没有向父进程报告的通道。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `JobStatus`、`JobControl` | `task/mod.rs` | `ProcessData` 增加受单锁保护的停止标志、待报告状态与 `continue_generation` 计数，外加 `cont_event` 等待集 |
| `do_job_stop()` | `task/signal.rs` | 记录停止，向父进程发 `SIGCHLD`（`CLD_STOPPED`），再在 `cont_event` 上以不可被普通信号打断的方式挂起 |
| `send_signal_to_process` | 同上 | 发送 `SIGCONT` 时置「已继续」并报告 `CLD_CONTINUED`；发送 `SIGKILL` 时强制清除停止，使其能被杀死 |
| `sys_waitpid` | `syscall/task/wait.rs` | 按 `WUNTRACED`/`WCONTINUED` 报告停止与继续，状态字分别为 `(signo << 8) | 0x7f` 与 `0xffff` |

「停止后紧接继续」的竞态用 `continue_generation` 处理：停止前取计数快照，若期间有 `SIGCONT` 使其递增，就不再挂起，效果等同于 Linux 在发送停止信号时清除排队的 `SIGCONT`、在发送 `SIGCONT` 时清除排队的停止信号。

影响范围：所有停止类信号与 `SIGCONT` 的投递，以及 `wait4`/`waitpid` 的返回。

与 Linux 的差异：Linux 的组停止逐线程进行（`JOBCTL_STOP_PENDING`，最后一个停下的线程通知父进程），这里以进程为单位；`ptrace` 相关的停止与报告没有涉及。当前 dev 把这套状态移到 `task/job_control.rs`，`JobStatus` 与 `continue_generation` 仍在。

## Linux 依据

- 发送停止信号时清除排队的 `SIGCONT`；发送 `SIGCONT` 时清除排队的停止信号、唤醒所有停止的线程，并准备向父进程报告 `CLD_CONTINUED`：[kernel/signal.c#L884-L931](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/signal.c#L884-L931)
- 取信号时对停止类信号执行 `do_signal_stop()`：[kernel/signal.c#L2967-L2989](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/signal.c#L2967-L2989)，组停止实现 [kernel/signal.c#L2553](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/signal.c#L2553)
- `wait` 的两种状态字：停止 `(exit_code << 8) | 0x7f`，[kernel/exit.c#L1383-L1384](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/exit.c#L1383-L1384)；继续 `0xffff`，[kernel/exit.c#L1433-L1435](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/exit.c#L1433-L1435)；未带 `WUNTRACED` 不报告停止 [kernel/exit.c#L1341](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/exit.c#L1341)，未带 `WCONTINUED` 不报告继续 [kernel/exit.c#L1408](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/kernel/exit.c#L1408)

## man 原文

[signal(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/signal.7?h=man-pages-6.19#n33)：

> Stop Default action is to stop the process.
>
> Cont Default action is to continue the process if it is currently stopped.

[wait(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/wait.2?h=man-pages-6.19#n127)：

> WUNTRACED also return if a child has stopped (but not traced via ptrace(2)). Status for traced children which have stopped is provided even if this option is not specified.
>
> WCONTINUED (since Linux 2.6.10) also return if a stopped child has been resumed by delivery of SIGCONT.

[wait(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/wait.2?h=man-pages-6.19#n196)：

> WIFSTOPPED(wstatus) // POSIX.1-2024 returns true if the child process was stopped by delivery of a signal; this is possible only if the call was done using WUNTRACED or when the child is being traced (see ptrace(2)).
>
> WSTOPSIG(wstatus) returns the number of the signal which caused the child to stop.
>
> WIFCONTINUED(wstatus) (since Linux 2.6.10) returns true if the child process was resumed by delivery of SIGCONT.

## 验证

- `test-job-control-stop`：父进程对忙等的子进程 `kill(SIGSTOP)` 后 `waitpid(WUNTRACED)` 得 `WIFSTOPPED` 且子进程仍存在；`kill(SIGCONT)` 后 `waitpid(WCONTINUED)` 得 `WIFCONTINUED`；`kill(SIGKILL)` 后得 `WIFSIGNALED && WTERMSIG == SIGKILL`。x86_64 单核实跑 15/15。
- `cargo xtask starry build --arch x86_64` 与 `cargo fmt --all -- --check` 通过。
