## 问题与原因

`sys_mlock2(_addr, _length, _flags)` 的函数体只有 `Ok(0)`，`sys_mlock` 转调它。任何参数都返回成功：不把页调入内存，范围内有未映射的页不报错，非法的 `flags` 也不报错。依赖 `mlock` 返回时页已常驻的程序得不到保证，用 `ENOMEM`、`EINVAL` 判断参数是否合法的程序得到错误的成功。

## 改动与影响范围

`sys_mlock2` 改为按以下顺序处理：

| 步骤 | 内容 |
|:--:|:--:|
| `flags` 校验 | 只接受 0 与 `MLOCK_ONFAULT`（`0x01`），其余返回 `EINVAL`，不产生任何副作用 |
| 零长度 | 直接返回 0 |
| 范围计算 | 起始地址向下对齐；`addr.checked_add(length)` 与对齐后的 `end < raw_end` 两处回绕检查，回绕返回 `EINVAL` |
| `flags == 0` | 调用 `populate_area(start, size, MappingFlags::READ)` 把整个范围调入，遇到未映射的页返回 `ENOMEM` |
| `MLOCK_ONFAULT` | 只用 `can_access_range`（空权限掩码）检查范围连续映射，有空洞返回 `ENOMEM`，不调入 |

`flags` 校验与页对齐回绕检查是两轮评审指出后补的。影响范围：`mlock` 与 `mlock2`。

与 Linux 的差异（合入时）：

- 没有锁定状态。补丁只调入页面，不在映射上记录「已锁定」，依据是内核没有交换，调入的页不会被换出。`munlock`、`mlockall`、`munlockall` 当时没有分发项，PR 正文也写明 `MCL_*` 不建模。`MLOCK_ONFAULT` 因此只剩一次覆盖检查。
- 不检查 `RLIMIT_MEMLOCK` 与 `CAP_IPC_LOCK`，Linux 在这里会返回 `EPERM` 或 `ENOMEM`。
- 范围内有空洞时两边的残留效果不同：Linux 先给空洞之前的映射打上锁定标志，返回 `ENOMEM`，不做调入；补丁在 `flags == 0` 时会把空洞之前的映射调入后才返回 `ENOMEM`。返回值一致。
- 长度接近 `usize::MAX`、加上页内偏移并向上取整后回绕为 0 的请求，Linux 按零长度处理并返回 0；补丁的 `checked_add` 在此返回 `EINVAL`。`addr + len` 回绕的一般情形两边都是 `EINVAL`。

当前 dev：`sys_mlock2` 在 `syscall/mm/mmap.rs` 第 1667 行。`flags` 校验、零长度、`raw_end` 的回绕检查（对齐改用 `checked_align_up`）与 `flags == 0` 时的 `populate_area` 都保留。此外补上了锁定状态：先按 `RLIMIT_MEMLOCK` 与 `CAP_IPC_LOCK` 判断并可能返回 `EPERM`，再用 `lock_vma_range` 在映射上记录 `Locked` 或 `LockOnFault`，然后才调入；`sys_munlock` 也已实现（第 1721 行）。合入时用 `can_access_range` 做的 `MLOCK_ONFAULT` 分支已被 `lock_vma_range` 取代。

## 溯源复核

- PR 正文与合入的 diff 不一致。正文写「MCL_* / MLOCK_ONFAULT 等 flag 细节暂不建模」，合入的代码校验了 `flags` 并为 `MLOCK_ONFAULT` 单独做了分支；正文也没有提页对齐回绕检查与新增用例。这些是评审后的提交加的，正文没有同步。
- 补丁只实现了「调入」与错误码，没有实现「锁定」本身：没有锁定状态、没有 `RLIMIT_MEMLOCK` 与权限检查、没有 `munlock`。当前 dev 已补上这三项，见上节。
- 回归用例已不在当前 dev 的树里，见「验证」。

## man 原文

[mlock(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/mlock.2?h=man-pages-6.19#n46)：

> mlock() locks pages in the address range starting at addr and continuing for size bytes. All pages that contain a part of the specified address range are guaranteed to be resident in RAM when the call returns successfully; the pages are guaranteed to stay in RAM until later unlocked.

[mlock(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/mlock.2?h=man-pages-6.19#n70)：

> The flags argument can be either 0 or the following constant: MLOCK_ONFAULT Lock pages that are currently resident and mark the entire range so that the remaining nonresident pages are locked when they are populated by a page fault.

[mlock(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/mlock.2?h=man-pages-6.19#n181)：

> EINVAL (mlock(), mlock2(), and munlock()) The result of the addition addr+size was less than addr (e.g., the addition may have resulted in an overflow).

[mlock(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/mlock.2?h=man-pages-6.19#n192)：

> EINVAL (mlock2()) Unknown flags were specified.

[mlock(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/mlock.2?h=man-pages-6.19#n214)：

> ENOMEM (mlock(), mlock2(), and munlock()) Some of the specified address range does not correspond to mapped pages in the address space of the process.

## 验证

- `test-mlock2`：对一页匿名映射，`mlock2(flags=0)` 返回 0，`mlock2(MLOCK_ONFAULT)` 返回 0，`mlock2(flags=0xFF)` 返回 `EINVAL`；对中间一页被 `munmap` 的三页范围，`mlock` 返回 `ENOMEM`。旧实现无条件返回 0，后两条断言在旧实现上不成立；PR 没有附修复前的运行记录，也没有给断言数量。
- 维护者批准时写明：当前提交的 CI（run `27050611336`）全部通过，含 x86_64、aarch64、riscv64、loongarch64 的 Starry QEMU 任务。PR 正文只写了 x86_64 内核编译通过。
- 缺口：用例没有覆盖地址回绕返回 `EINVAL` 的两条路径（维护者在批准意见里记为不阻塞的缺口），没有检查 `flags == 0` 成功后页确实已调入，也没有检查非法 `flags` 不产生调入。
- 当前 dev 的树里已没有 `test-mlock2`。目录后来移到 `test-suit/starryos/qemu/system/syscall-test-mlock2`，最后一次改动它的提交是 #2404（`test(starry): migrate bugfix and syscall probes to LTP`，`1564626a04`，2026-09-14），此后目录不存在。接替它的 `ltp-syscalls/cases.txt` 里与 `mlock` 相关的只有 `mlock202` 一条，是否覆盖原用例的四条断言没有核对。
