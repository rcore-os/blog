## 问题与原因

打开已存在的文件时不检查属主、属组、其他人的权限位。凭据只在创建新文件时用来检查父目录的写权限；文件已经存在时，路径解析完就直接构造文件对象。非特权进程因此可以读写权限位不允许的文件，`O_TRUNC` 还会把它清空。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| 是否新建 | `axfs-ng-vfs` 的 `open_or_create` | 同时返回「这次调用是不是新建了文件」 |
| 权限回调 | `ax-fs-ng` 的 `OpenOptions::may_open` | 在 `_open` 里对同一个 `Location` 检查，位于「以写方式打开目录返回 `EISDIR`」之后；`O_PATH` 与本次新建的文件跳过 |
| 接线 | `syscall/fs/fd_ops.rs` 的 `flags_to_options` | `openat`、`openat2`、经 `/proc/self/fd` 重开三条路径都装上检查 |
| 判定 | `syscall/fs/stat.rs` 的 `check_dac_access` | 复用 `faccessat2` 的判定；`O_TRUNC` 计入写访问，`O_APPEND` 不计 |

内核内部直接用 `OpenOptions` 的路径（装载程序、挂载、socket 绑定）不装检查。

这个 PR 没有合入。09.21 维护者 `Josen-B` 关闭了它，同一天合入他自己的 [#2468](https://github.com/rcore-os/tgoskits/pull/2468)（对应 issue #1761），做的是同一件事。当前 dev 上的实现来自 #2468：`OpenOptions::_open()` 带 `newly_created` 参数，不是新建时调用 `check_open_access()`，`O_PATH` 跳过，读与写分别要求对应权限位，`O_TRUNC` 计入写。结构与本 PR 相同：检查与打开作用于同一个 `Location`，新建的文件不查。本 PR 的用例 `bugfix-openat-dac-permission` 不在 dev 上。

## 溯源复核

- 第一版在 `sys_openat` 里先按路径检查、再按路径打开。评审指出五个问题：经 `/proc/self/fd` 重开与带 `resolve` 的 `openat2` 绕过检查；两次解析之间文件可以被替换；忽略 `CAP_DAC_OVERRIDE`；把 `EISDIR`、`ENOTDIR` 变成 `EACCES`；`O_RDONLY|O_APPEND` 被误要求写权限。这五条都成立，后来的版本把检查下沉到 `_open` 才解决。
- 09.15 的一条评审意见是「持有 `CAP_DAC_READ_SEARCH` 时 `O_RDWR` 应当放行」。对照 Linux 源码与宿主实测，这条不成立：该能力只在请求的访问恰好是只读时才旁路，`O_RDWR` 仍是 `EACCES`。本地记录里有逐行的依据，当时补了组合权限的用例。
- 09.15 另一轮的三条阻塞意见都是基线漂移：dev 在此期间合入了 #2287（路径逐级的搜索权限与 `openat2` 的 `resolve` 检查），本分支落后时这些检查在 diff 里显示为被删除。变基后消失。
- 最后一轮评审（09.15）仍留有一条关于竞态的意见，PR 关闭前没有再处理。
- PR 讨论里没有写关闭原因；「被 #2468 取代」是由关闭人、#2468 的合入时间与 dev 上的代码推出的。

## man 原文

[open(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/open.2?h=man-pages-6.19#n983)：

> EACCES The requested access to the file is not allowed, or search permission is denied for one of the directories in the path prefix of path, or the file did not exist yet and write access to the parent directory is not allowed.

## 验证

数字取自 PR 正文，都是这个 PR 自己分支上的结果。

- `bugfix-openat-dac-permission`：root 建 0644 的文件与 0555 的目录，子进程降权到 uid 1000。普通 `open`：只读与 `O_RDONLY|O_APPEND` 成功，写、`O_TRUNC`、对已存在文件的 `O_CREAT|O_WRONLY` 都是 `EACCES` 且文件不被截断，以 0444 新建的文件本次可写。错误码次序：目录写访问 `EISDIR`，文件带尾斜杠 `ENOTDIR`。经 `/proc/self/fd` 重开与 `openat2` 同样受限。保留 `CAP_DAC_OVERRIDE` 时 `O_WRONLY` 成功。
- x86_64，基线 `1d7f3c20`：只加用例时 14 过 3 挂，写入与截断全部成功；加上修复后 17 项全过。变基到 `e8f4400b` 并补两组用例后，上一版 21 过 2 挂，新版 23 项全过。
- 宿主 Linux 6.6 上以 root 与非 root 各实跑一遍，结果与期望相同。
