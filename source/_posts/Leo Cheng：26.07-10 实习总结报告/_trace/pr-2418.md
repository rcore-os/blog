## 问题与原因

PTY master 关闭时要移除 `/dev/pts/N` 名称，但若 slave 仍有打开引用，PTY 本身和该 index 仍在使用；只有两端都关闭后 index 才能重新分配。原 StarryOS 缺少跨主从端共享的生命周期记账，设备析构、目录项缓存和 index 释放没有同一状态源，造成反复创建 PTY 后 index 耗尽或复用时旧路径仍指向旧 slave。

## 改动与影响范围

PR 为 PTY 主从端增加共享 `PtyLinkState` 计数，master 关闭时隐藏 slave 节点，最后一端关闭时移除条目并归还 index；`PtsDir` 禁用目录项缓存，避免 index 复用后缓存继续指向前一个设备。此 PR 主要处理下标分配与节点可见性，初版仍未把 peer hangup 状态与 reopen 生命周期同步，相关从端重开问题由 #2417 提出；两项最终在 [#2426](pr-2426.md) 的 `PtyLink` 状态中统一处理。本 PR 已关闭，没有单独合入。

## Linux 依据

- Linux 在 master 关闭时调用 `devpts_pty_kill()` 移除 slave inode，但此动作不等同于回收 PTY index：[drivers/tty/pty.c#L47-L75](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/pty.c#L47-L75)、[fs/devpts/inode.c#L548-L562](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/fs/devpts/inode.c#L548-L562)
- index 在 Unix98 PTY 的 remove 路径中释放；该回调在 PTY 两端最终关闭、tty 对象销毁时执行：[drivers/tty/pty.c#L702-L714](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/pty.c#L702-L714)

## man 原文

[`pts(4)`](https://man7.org/linux/man-pages/man4/pts.4.html) 说明打开 `/dev/ptmx` 会创建一对 PTY master/slave，并在 `/dev/pts` 创建 slave 节点。节点删除与 index 何时可复用属于内核对象生命周期，man 页面没有规定具体回收实现，以上游源码为准。

## 验证
