## 问题与原因

dnsmasq 的接口发现在 StarryOS 上失败。PR 正文给出的链路是：musl 的 `if_indextoname(3)` 在一个 `AF_UNIX` 套接字上发 `SIOCGIFNAME`，内核不认识这个命令，返回 `ENOTTY`。

落到代码上有两层。

- `SIOCGIFNAME`（0x8910）没有实现。`Socket::ioctl` 的 `match` 里有 `SIOCGIFINDEX` 等查询命令，没有它的逆操作。
- 接口类 ioctl 的处理分散在各套接字类型里。全部分支写在 `impl FileLike for Socket` 的 `ioctl` 里；`NetlinkSocket` 没有自己的 `ioctl`；`PacketSocket::ioctl` 是另一份只含 `SIOCGIFINDEX`、`SIOCGIFFLAGS`、`SIOCGIFHWADDR` 的实现，带着自己的 `ifreq_interface`、`write_ifreq_data`、`linux_flags` 副本，并且先按 `ifr_name` 找接口、再看命令号，未知命令也可能得到 `ENODEV` 而不是 `ENOTTY`。同一个命令在不同地址族的套接字上结果不同。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `device_ioctl(cmd, arg)` | `file/net.rs` | 新增。把 `Socket::ioctl` 里的 `SIOCGIFCONF`、`SIOCGIFFLAGS`、`SIOCSIFFLAGS`、`SIOCGIFADDR`、`SIOCGIFDSTADDR`、`SIOCGIFBRDADDR`、`SIOCGIFNETMASK`、`SIOCGIFHWADDR`、`SIOCGIFMTU`、`SIOCGIFMETRIC`、`SIOCGIFMAP`、`SIOCGIFTXQLEN`、`SIOCGIFINDEX`、`SIOCETHTOOL` 原样搬进来；命令不归它管时返回 `None`，由调用方继续尝试自己的命令或返回 `ENOTTY` |
| `SIOCGIFNAME` | 同上 | 从 `ifreq` 偏移 16 处读 4 字节的 `ifr_ifindex`，用 `visible_interface_by_id` 查接口，查不到返回 `ENODEV`；把名字写到偏移 0，补零到 16 字节（`write_ifreq_name`） |
| `SIOCGIFSLAVE` | 同上 | 按名字找接口，找不到返回 `ENODEV`，找到返回 `EINVAL`；此前是 `ENOTTY` |
| `Socket::ioctl` | 同上 | 改为：`FIONREAD`，再 `device_ioctl`，再无线扩展命令，最后 `ENOTTY` |
| `NetlinkSocket::ioctl` | `file/netlink.rs` | 新增，调用 `device_ioctl`，其余返回 `ENOTTY` |
| `PacketSocket::ioctl` | `file/packet.rs` | 改为调用 `device_ioctl`，删除私有的三个辅助函数与相关常量 |

影响范围：所有套接字上的接口类 ioctl。`AF_NETLINK` 套接字从不应答变为应答整组命令；`AF_PACKET` 套接字从三个命令扩到整组。

`AF_PACKET` 上有三处随之改变的既有行为，PR 正文没有提：`SIOCGIFHWADDR` 查回环接口原先因没有 MAC 返回 `ENODEV`，现在返回 `ARPHRD_LOOPBACK` 与全零地址；未知命令原先先读 `ifr_name` 并查接口，现在直接返回 `ENOTTY`；非根网络命名空间里原先一律 `ENODEV`，现在由 `device_ioctl` 内部的查找函数决定可见性。

与 Linux 的差异：

- Linux 的通用路径只管设备级命令。`SIOCGIFADDR`、`SIOCGIFBRDADDR`、`SIOCGIFNETMASK`、`SIOCGIFDSTADDR` 由地址族自己的 `ioctl` 处理：`AF_INET` 走 `inet_ioctl()` 进 `devinet_ioctl()`，`AF_PACKET` 转给 `inet_dgram_ops.ioctl`；`AF_UNIX` 与 `AF_NETLINK` 的 `ioctl` 对它们返回 `-ENOIOCTLCMD`，落到 `dev_ioctl()` 的默认分支得到 `ENOTTY`。StarryOS 把这四个命令也放在共享的 `device_ioctl` 里，`AF_UNIX`、`AF_NETLINK` 套接字都能查到地址。
- 次序上 Linux 先问地址族自己的 `ioctl`，返回 `-ENOIOCTLCMD` 才进 `dev_ioctl()`；StarryOS 先进 `device_ioctl`。对补丁涉及的命令结果相同。
- `SIOCGIFMAP` 返回全零、`SIOCGIFTXQLEN` 固定返回 1000、`SIOCETHTOOL` 返回 `EOPNOTSUPP`，这些是搬迁前就有的简化，本 PR 未改。

当前 dev：`device_ioctl` 在 `os/StarryOS/kernel/src/file/net.rs` 第 366 行，签名多了 `current` 参数；`SIOCGIFNAME` 分支在第 374 至 383 行，`SIOCGIFSLAVE` 在第 486 至 489 行。三个调用点是 `net.rs` 第 874 行、`netlink.rs` 第 660 行、`packet.rs` 第 290 行。[#1566](pr-1566.md) 之后 `SIOCSIFMTU`、`SIOCSIFADDR`、`SIOCSIFNETMASK`、`SIOCADDRT`、`SIOCDELRT` 也加进了这个函数。

## 溯源复核

- PR 正文称「Linux 把 `SIOCGIF*` 经 `sock_ioctl` 到 `dev_ioctl` 统一路由，与地址族无关」。这对 `dev_ioctl()` 里的那一组成立（`SIOCGIFNAME`、`SIOCGIFHWADDR`、`SIOCGIFFLAGS`、`SIOCGIFMETRIC`、`SIOCGIFMTU`、`SIOCGIFSLAVE`、`SIOCGIFMAP`、`SIOCGIFINDEX`、`SIOCGIFTXQLEN`、`SIOCETHTOOL`，以及 `sock_ioctl()` 直接处理的 `SIOCGIFCONF`），对四个地址查询命令不成立，见上文差异。合入后 `ioctl(netlink_fd, SIOCGIFADDR)` 在 StarryOS 上成功，在 Linux 上是 `ENOTTY`。#1566 把设置地址与路由的命令加进同一个函数后，这个出入扩大到 `SIOCSIFADDR`、`SIOCSIFNETMASK`、`SIOCADDRT`、`SIOCDELRT`（Linux 上这些也只有 `AF_INET` 与 `AF_PACKET` 套接字应答）。当前 dev 未区分。
- 正文称补丁之前非 `AF_INET` 套接字不应答其余 `SIOCGIF*`。从 diff 看，这些分支原本就在通用的 `Socket::ioctl` 里，`AF_UNIX` 与 `AF_INET` 共用这个类型，缺的只是 `SIOCGIFNAME`；这句话对 `AF_NETLINK` 成立，对 `AF_PACKET` 部分成立（只有三个命令）。
- musl 的 `if_indextoname(3)` 用 `AF_UNIX` 套接字这一点来自 PR 正文，本文没有对照 musl 源码，待核实。回归用例没有直接在 `AF_UNIX` 套接字上发 ioctl，只通过 `if_indextoname("lo")` 的往返间接覆盖。
- 用例注释把「先拷入 `ifreq` 再查找」归到 `net/socket.c` 的 `dev_ifname`。拷入发生在 `sock_do_ioctl()` 的 `get_user_ifreq()`，`dev_ifname()` 在 `net/core/dev_ioctl.c`。断言本身（空指针返回 `EFAULT`）与 Linux 一致。
- [#1568](pr-1568.md) 的正文曾写 `SIOCGIFNAME` 由 #1566 提供，实际由本 PR 提供。

## man 原文

[netdevice(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/netdevice.7?h=man-pages-6.19#n19)：

> Linux supports some standard ioctls to configure network devices. They can be used on any socket's file descriptor regardless of the family or type.

[netdevice(7)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man7/netdevice.7?h=man-pages-6.19#n81)：

> SIOCGIFNAME Given the ifr_ifindex, return the name of the interface in ifr_name. This is the only ioctl which returns its result in ifr_name.

手册的第一句没有区分命令。按上面列的源码，这句话对设备级命令成立，对地址查询命令在 `AF_UNIX`、`AF_NETLINK` 套接字上不成立。
