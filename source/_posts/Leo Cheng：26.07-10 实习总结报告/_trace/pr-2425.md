## 问题与原因

TTY 的 `TIOCGPGRP`/`TIOCSPGRP` 读写前台进程组时，StarryOS 原先直接使用全局 PGID。调用者位于嵌套 PID namespace 时，同一个进程组在该 namespace 中可能有不同编号，也可能完全不可见；返回全局编号或用全局表查输入都会违反调用者可见的 PID 语义。

## 改动与影响范围

PR 将 ioctl 的编号转换改为 `PidView`：`TIOCGPGRP` 用调用者 namespace 输出可见 PGID，不可见时写出 0；`TIOCSPGRP` 在同一 namespace 解析输入 PGID。范围仅限 tty 前台进程组 ioctl，不改变终端会话资格检查、前台组权限规则或 tty 生命周期；整个修改与回归测试后来并入 [#2426](pr-2426.md)，本 PR 于 2026-09-25 关闭。

## Linux 依据

- Linux `tiocgpgrp()` 通过 `pid_vnr()` 输出 caller-visible 的进程组编号：[drivers/tty/tty_jobctrl.c#L466-L478](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/tty_jobctrl.c#L466-L478)
- Linux `tiocspgrp()` 用 `find_vpid()` 解析调用者 namespace 中的 PGID，再验证它属于调用者的 session：[drivers/tty/tty_jobctrl.c#L493-L524](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/drivers/tty/tty_jobctrl.c#L493-L524)

## man 原文

[`tcgetpgrp(3)`](https://man7.org/linux/man-pages/man3/tcgetpgrp.3.html) 将返回值定义为与控制终端关联的 foreground process group ID；[`ioctl_tty(2)`](https://man7.org/linux/man-pages/man2/ioctl_tty.2.html) 列出 `TIOCGPGRP` 与 `TIOCSPGRP` 作为对应 ioctl。PID namespace 内编号映射细节由 Linux 源码补足，man 手册不展开这一点。

## 验证

新增嵌套 PID namespace 回归验证：namespace 不可见的 foreground PGID 由 `tcgetpgrp()` 返回 0；可见 session 下的 `tcsetpgrp()`/`tcgetpgrp()` 往返一致。原 PR 的人工 PTY 用例没有执行 `TIOCSPTLCK` 解锁，因此宿主 Linux 验证证据有缺口；合并到 #2426 后，最终用例在打开从端前显式解锁，并纳入 tty 五项回归。26.04 记录的最终 StarryOS tty 分组为 `520/520`，原 PR head 的四架构 QEMU suites 通过。
