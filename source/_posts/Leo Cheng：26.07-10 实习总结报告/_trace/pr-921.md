## 问题与原因

两处与真实网络服务相关的 ABI 偏差：

1. `starry-vm` 的 `vm_read_slice`/`vm_write_slice` 要求用户指针按 `align_of::<T>()` 对齐，否则返回 `BadAddress`。Linux 的 `copy_to_user`/`copy_from_user` 按字节语义工作，不要求用户缓冲区对齐。Go 的 `[]epollevent` 只按 4 字节对齐，riscv64 与 loongarch64 上 `struct epoll_event` 按 8 字节对齐，于是 `epoll_pwait` 回写事件时报 `EFAULT`，Go 运行时启动即 `netpoll failed`，这两个架构上所有 Go 网络服务（prometheus、consul、etcd、minio）都起不来。`notes/71` 在 6 月 4 日插桩坐实的就是这道检查。[#914](pr-914.md) 已把 epoll 的两个调用点改成按字节拷贝、不会触发它，note 71 所用分支没有包含 #914，因此仍然命中；本拉取请求在底层删除检查，覆盖所有调用点。
2. `NetlinkSocket` 不是 axnet 套接字，`recvmsg` 走无标志的读取路径，每次都弹出队首消息：`MSG_PEEK` 变成消费，`MSG_TRUNC` 不报完整长度，`MSG_DONTWAIT` 被忽略。glibc 与 musl 的 `getifaddrs()` 先用 `MSG_PEEK|MSG_TRUNC` 探测长度再正式读，第二次读永久阻塞。

## 改动与影响范围

| 修改点 | 位置 | 内容 |
|:--:|:--:|:--:|
| `vm_read_slice` / `vm_write_slice` | `starry-vm/src/lib.rs` | 去掉对用户指针的对齐检查；各架构 `user_copy` 本就处理任意对齐 |
| `NetlinkSocket::read_one(peek, truncate)` | `file/netlink.rs` | 窥视时复制队首而不弹出；截断时返回完整报文长度 |
| `NetlinkSocket::recv()` | 同上 | 新增，`MSG_DONTWAIT` 做一次非阻塞轮询 |
| netlink 接收路径 | `syscall/net/io.rs` | `recvmsg`/`recvfrom` 把三个标志传给 netlink |

影响范围：第一处改的是所有系统调用共用的用户内存拷贝函数，凡是经它读写用户缓冲区的调用都不再因对齐失败；内核侧缓冲区本就对齐，只放宽了用户指针。第二处只影响 netlink 套接字，`read(2)` 仍是消费语义。

当前 dev 均保留：`starry-vm` 中已无对齐检查，`netlink.rs` 第 570 行 `read_one(dst, peek, truncate)`。

## Linux 依据

- `copy_to_user`/`copy_from_user` 只检查长度与对象大小，然后交给 `raw_copy_*`，没有对齐判断：[include/linux/uaccess.h#L215-L238](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/include/linux/uaccess.h#L215-L238)
- netlink 接收：`skb_recv_datagram(sk, flags, ..)` 处理 `MSG_PEEK` 与 `MSG_DONTWAIT`（[net/netlink/af_netlink.c#L1921](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/netlink/af_netlink.c#L1921)，窥视分支 [net/core/datagram.c#L335](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/core/datagram.c#L335)）；缓冲区不够时置 `MSG_TRUNC`，调用方带 `MSG_TRUNC` 时返回完整长度：[net/netlink/af_netlink.c#L1950-L1952](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/netlink/af_netlink.c#L1950-L1952)、[net/netlink/af_netlink.c#L1974-L1975](https://github.com/torvalds/linux/blob/8cd9520d35a6c38db6567e97dd93b1f11f185dc6/net/netlink/af_netlink.c#L1974-L1975)

## man 原文

[recv(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/recv.2?h=man-pages-6.19#n104)：

> MSG_DONTWAIT (since Linux 2.2) Enables nonblocking operation; if the operation would block, the call fails with EAGAIN or EWOULDBLOCK.

[recv(2)](https://git.kernel.org/pub/scm/docs/man-pages/man-pages.git/tree/man/man2/recv.2?h=man-pages-6.19#n216)：

> MSG_PEEK This flag causes the receive operation to return data from the beginning of the receive queue without removing that data from the queue. Thus, a subsequent receive call will return the same data.
>
> MSG_TRUNC (since Linux 2.2) For raw (AF_PACKET), Internet datagram (since Linux 2.4.27/2.6.8), netlink (since Linux 2.6.22), and UNIX datagram as well as sequenced-packet (since Linux 3.4) sockets: return the real size of the packet or datagram, even when it was longer than the passed buffer.

## 验证

- 第一处：qemu-10 单核四架构跑 prometheus（启动、本地回环 HTTP 就绪、PromQL 查询），riscv64 与 loongarch64 由 `netpoll failed` 转为 `PROM_OK=1`，x86_64 与 aarch64 无回归。
- 第二处：netlink「先窥视再读」由永久阻塞转为正常返回。
- 回归用例随拉取请求提交：`test-epoll-pwait2` 覆盖未对齐的事件缓冲区，`test-netlink-recvmsg` 覆盖三个标志。
